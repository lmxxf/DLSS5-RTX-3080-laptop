## 2. 必须修正的硬账

### 2.1 运行总数重复计入 V3.3 的 12 次探针基线

对应原稿第 6、24、128 行。

V3.3 的 `validation.counts` 为 `smoke=33, probes=84, bench=240, repeat=24`，相加为 **381**，不是 393。`strict_successful_runs=309` 已包含探针阶段的 **12 次 baseline**，再加整个 84 次探针对照就重复计入这 12 次。

按报告自引四份 `validation.counts` 的同一账本口径：

|轮次|记录的进程数|
|---|---:|
|v32|411|
|v33|381|
|v34|162|
|v35|192|
|合计|**1,146**|

因此 `1,026 + 132 = 1,158` 应修正为此口径的 **1,014 + 132 = 1,146**。其中包括快验与 v32 排除筛查，不应全称作有效候选跑分。v35 的 construction-validation 另存 24 次初始构造快验，未在上述计数中；如要纳入，应另列口径，不能把“账本计数”“所有 GPU 进程”“GPU 原语调用”混成一个总数。

### 2.2 “28 个功能候选”实际是 33 个

对应第 35、84 行。表格行数和各轮配置数为 **11 + 10 + 5 + 7 = 33**；加共享 baseline 才是 34 个命名配置。33 个功能配置只有 **31 个不同 DLL SHA**。部分版本由既有 cubin 重新组装，也不能不加定义地称为“34 个独立编译版本”。

### 2.3 36 是 144 的子集，不能合成“180 项独立反证”

对应第 112～113 行。这是集合错误，不是措辞问题。

按 `(FB, kernel, run, register)` 联结两个文件：

- v33 混合事件集合：144；
- v34 `pack_multidef` 集合：36；
- 交集：36；并集：**144**。

所以第 113 行“全部 180 项”错误。这些证明排除了相应事件上的**无条件 fallback-native 替换**；既不覆盖所有 5,848 项的全部改写方法，也不证明条件化转发、内存表示重写、跨阶段复用均不可能。v35 自身已经通过改变 Shared 表示免掉了部分原读端解码，正好说明“原表示下不能直接转发”与“不能改写表示”不同。

### 2.5 FB02 新增 spill 不是 176/163，实际 REG 也没有越过 168

对应第 31、119 行：

- `176/163` 是 `fb2_exact_shadow` 的 **38 核全网** STL/LDL；

## 3. 上限论证尚未成立

### 3.1 K=3 剪枝不是搜索完备性证书

对应标题及第 24、127～133 行。四个预设节点全部 Pruned，是搜索控制状态；它不枚举所有满足固定 Host/ABI、固定发射序列、原槽 O4 的 PTX 程序，也没有证明四种机制是独立且完备的划分。共享整数管线、寄存器、排程、内存等因素还存在交互，“正交四维”不能当作数学分解。

预先固定晋升门并正确拒绝候选值得保留；但“没有通过门”不等于真实平均收益恒为零，更不等于任何未测试程序也过不了门。当前每方向主要是两个进程 GPU median 的比较，没有定义最小可检测收益、收益上界置信区间或等效性检验。不能靠增加失败次数的叙事分量补出这些证明。

### 3.2 5-SASS / 4-SASS 是已实现序列，不是已证 ISA 下界

对应第 95～105、130 行。

把五项代数工作分别对应到五条指令，不能证明少于五条指令不存在；本序列自身就在用 `HMNMX2 |x|` 与 `LEA` 合并多种操作。也没有覆盖输入范围特化、不同表示、跨转换公共子表达式或重用方式。`shift` 两种等价写法失败、某个 packed 立即数语法被拒绝，都不能构成指令集穷举证明。

更应修正第 97 行的精度表述：当前 pack5 是既定的近似/ties-toward-zero 基线，与原先 RN-even 路径并非全位型一致；不能将其称为完整“IEEE 754 转换代数下界”。v32～v35 的精确验证是**相对 V3.1_pack5** 的位一致，不是重新证明它等价于原始 NVIDIA 转换或 FP32 真值。

“FP8 数据在进入 Ampere 的 FP16 MMA 前要获得兼容表示”成立；“每次 Global load 必须付固定四条 SASS/half2，且不能用更低成本的组织/复用方式”没有被证明。

### 3.3 原型失败没有证明普遍的缓存/Spill 最优平衡

对应第 106～109 行。`112→28` 是虚拟 decoder 池变化，不是总物理寄存器生命周期的穷尽优化。源码 remat 被合并而资源计数相同，甚至不等于所有机器码逐字节相同；构造 `call` 控制的 67%～73% 回退还包括调用 ABI 与保存/恢复开销，不能作为无调用边界重算的成本下界。

第 93 行也应只说“网格小于基线理论容量，不可从驻留台阶直接推出增加容量波次”；没有 achieved occupancy / 实际并发 CTA 计数，不能直接写成测得实际并发数完全未变。

### 3.4 Shared 有真实负结果，但 LSU/银行冲突的普遍因果未分离

对应第 115～121 行：

- 独立 shadow 保留原 store，再写 2× 扩展视图；镜像位置的**源级总写入字节为 3×**，不是统一 2×。读端还区分保留旧视图与 DCE。原位版本的 2× 与独立 shadow 应分开。
- 没有实测 Shared bank conflict、LSU issued/吞吐或时序 stall 计数。字节数翻倍不能推出银行冲突翻倍；静态 SASS 数增加也不是动态 LSU 发射量证明。
- fast_shadow 保留原 FP8 副本，因此不能统称所有 fast 版本都省掉全部写端 pack5；原位 fast 才更直接消除这批生产者 pack。
- 表中仍有单档正收益和方向变号，不能把“全部未过全档晋升门”写成每一档“全线变慢”。

可保留的结论是：“本轮七个具体表示改写，在质量门下均未取得首轮全档双向净胜。”不能由此推成“FP8 压缩交换在 sm_86 上总是优于 FP16 交换，任何后续削减都会有更大代价”。

## 4. 在声明的边界内仍未排除哪些方向

这里没有宣称它们已经可兑现，也不要求现在盲目跑一遍；它们说明当前报告的完备性命题为什么不成立。

1. **FB04/05 的异步耦合表示没有被 V3.5 实测。** `candidates.json` 的非 baseline 目标模块并集只有 `{1,2,3}`；`analyze.py` 的 `eligible_shadow` 是主动限定 FB01～03、排除 cp.async 别名。这个原型筛选不能变成同一 Host/ABI 内无法改造异步发布、分区解包或生产者/消费者协同布局的证明。尤其 FB04 的部分核在额外 Shared 容量下仍可保持当前驻留；增加核内部协作/同步不必然需要改 Host 参数或增加 Host 发射。槽位能否装入、精度和净收益都需要另行构造验证，当前未被排除。
2. **原位与按入口选择的覆盖尚不完备。** 原位 exact/fast 只有 FB01；FB02/03 采用保留原视图的 shadow。整模块负收益不能排除按真实 REG/STACK/读写复用选取部分入口或存取段。有限测试可以决定“不继续投入”，不能证明这些组合均不满足边界。
3. **已有范围保证的 pack 特化仍缺分析。** 若某些转换的生产者已明确饱和、非负或有界，就可能不需要通用转换的全部前端操作；这须先证明范围与非有限值行为再做原语/实测。报告没有这项覆盖，因此不能用通用 pack5 的五步表排除它。可能无净收益，但当前并未证明无净收益。

以上是**未排除方向**，不是已发现一个保证更快的实现。当前没有经过两轮验证、可替代 V3.1 的新 DLL；这一点与“仍没有上限证明”完全可以同时成立。
