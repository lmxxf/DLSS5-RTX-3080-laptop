# 2026-10-24 多定义过滤/去量化控制实验与部署

本轮将两个因素拆开，均保留其它转换和MMA映射：

- strict_nq：原严格同基本块、单定义资格检查，不加mapped源量化。
- multidef_nq：仅以entry内全指令定义计数拒绝多定义pack目标、FP8中间寄存器和FP16来源；允许单定义跨基本块。不加mapped源量化。

两版均拒绝受谓词控制的pack/down，要求down文本顺序在pack之前；“仅多定义”没有删掉这些基础匹配条件。通过检查的mapped恢复原shfl/shfl/selp路径。均独立重编FB0..5；FB6无mapped、FB7..14无对应网络转换，沿用已经验证的同源O4结果。

## 结果

两版15/15 O4，所有15个Fatbin均塞回原槽位，均未添加PE节。

|版本|720p天空 GPU median|900p原bench GPU median|1080p原bench GPU median|天空变号|天空高频RMS|
|---|---:|---:|---:|---:|---:|
|strict_nq|17.886ms|31.756ms|37.113ms|0|.000109039|
|multidef_nq|15.829ms|24.474ms|32.036ms|0|.000102701|

各档warmup5、测量20，preset2/style1，全部nonfinite=0。720p是天空，900p/1080p为原bench场景，与前轮相同。两版依次测，存在温度/频率顺序影响。多定义过滤版已回到旧错误fast约16/24/32ms速度范围，同时没有天空红绿横带；PNG已目视核验。

这组控制实验证明：在当前天空复现上，恢复显式量化不是消除横带的必要条件；排除非法多定义映射是关键修复。严格跨块拒绝及额外量化都增加了当前实现成本。没有将这结论扩大为任意输入下转发与完整E4M3路径逐位等价。

构建：nq-controls-build.log；实测：nq-controls-results.txt/.json；逐档日志：strict_nq-* / multidef_nq-*；图：multidef_nq-output.png；布局：multidef_nq-manifest.json。
