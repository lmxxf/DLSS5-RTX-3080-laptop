## 一、 核心结论：正交消融揭示的真实性能敏感度与优化方向

1. **生产版本定位**：
   - **`PTX V2.7` 是当前经过完整质量与配对性能验证的生产推荐版本**。在 `V2.6`（线程内 Low/High K16 拆解消除 70% `mapped` 操作数的 `PRMT` 与解码临时池）基础上，`V2.7` 将 `FB00` 中 4 个 C32 核（`pre_block`、`inpview_tilesync`、`ds_wait`、`outview_wait`）的 `.maxnreg` 设为 `168`（理论驻留上限从 `8 Warps/SM` 升至 `12 Warps/SM`），在未插桩四进程正反 ABBA 对照中较 `V2.6` 再降耗时 **`0.938%`（720p：`6.07900 → 6.02200 ms`）/ `0.670%`（900p：`8.83875 → 8.77950 ms`）/ `0.975%`（1080p：`11.61700 → 11.50375 ms`）**，170 次运行（160 次 50/80 正式运行 + 10 次 1/1 快验）相对 `V2.6` 严格 `0 bit-diff`。
   - `V2.8` 针对 `FB05 (ViT)`、`FB04 (C512)` 及 `FB00 upsample` 已测试的 10 项单核/分层及 1 项组合 `.maxnreg` 压降控制实验（275 次运行：240 次单项正式 + 24 次组合正式 + 11 次快验）均未获得三档分辨率一致的正向净收益（其中 0 spill 的 `vit_contract` 在 720p 下回退 `-0.882%`），证实该批已测试的 `.maxnreg` 压降配置在其余模块上无全档稳定正收益。

2. **5 版本正交消融实验（`V2.7 / P0 / P1 / P2 / P3`）的核心发现**：
   为诊断 `PTX V2.7` 剩余的指令与寄存器压力敏感度，我们在 `V2.7` 基线上构建了 **2×2 正交因子探针（`Decode × Pack`）** 及 **单拍 MMA 探针（`P3`）**，通过五版本正反序四轮未插桩测试（60 次进程运行，每次 50 warmup / 80 iter）与 NVAPI 82 次发射逐核捕获（30 次进程运行，每次 50 warmup / 20 iter），测得以下关键现象（注：探针通过删改指令改变程序行为以测量条件性能敏感度，非等价网络输出，亦非将原程序时间唯一分解为互斥的独立物理计时器）：
   - **发现 ①：在 `V2.7` 基线上，独立移除非 `mapped` 解码（`V2.7 → P1_ZeroDecode`）与独立移除 SWAR 打包（`V2.7 → P0_ZeroPack`）均表现出显著的正向性能敏感度**：
     - **独立去 Decode 主效应（`V2.7 − P1`）**：未插桩四轮均值下降 **`0.576 ms (-9.76%)` / `1.109 ms (-12.53%)` / `1.535 ms (-13.15%)`**（NVAPI 核内合计下降 `0.540 / 1.160 / 1.608 ms`）。38 个活跃 FP8 核的静态 SASS 指令减少 `45,914` 条（`-26.1%`），`PRMT` 减少 `11,428` 条（`-57.5%`），`STL/LDL` 栈溢出读写从 `109/108` 条降至 `39/28` 条（`FB01` 活跃核最大 `STACK` 从 `96 B` 降至 `32 B`）。
     - **独立去 Pack 主效应（`V2.7 − P0`）**：将 `v22/codegen.py` 的 20 条 PTX SWAR `FP16x2→FP8x2` 打包（5 个 `.b32` 临时寄存器）替换为单条 `cvt.u16.u32` 后，未插桩四轮均值下降 **`0.415 ms (-7.02%)` / `0.570 ms (-6.45%)` / `0.573 ms (-4.91%)`**（NVAPI 核内合计下降 `0.390 / 0.517 / 0.579 ms`）。38 个活跃核静态 SASS 减少 `39,214` 条（`-22.3%`），`STL/LDL` 从 `109/108` 降至 `81/79`（`FB01` 最大 `STACK` 从 `96 B` 降至 `80 B`）。其中 720p 下 **`FB05 (ViT)` 单模块对去 Pack 的敏感度达 `+0.178 ms`（超过其对去 Decode 的 `+0.067 ms`）**。
   - **发现 ②：`Decode` 与 `Pack` 之间存在强烈的亚加性负交互项（`Interaction = -0.394 / -0.660 / -0.810 ms`）**：
     - 当在已经移除 Decode 的 `P1` 上继续移除 Pack（`P1 → P2_Both`）时，条件净变化骤降至 **`+0.021 ms`（720p）/ `-0.090 ms`（900p）/ `-0.237 ms`（1080p）**（900p/1080p 出现回退）。
     - **原因解释**：在 `V2.7` 中，non-mapped 解码与 SWAR 打包共同争抢 SM 整数/置换指令发射资源与物理寄存器窗口；当 `P1` 率先移除解码与 20~112 个 `.b32` 解码临时寄存器池后，寄存器溢出与整数发射压力已大幅缓解，此时再移除 SWAR 打包不仅边际收益消失，反而因改变了部分核的指令调度与访存写回节奏而在 `FB00/13/14` 上引起轻微回退。
   - **发现 ③：去 `Decode` 条件下的单拍替代计算探针（`P3_ZeroDecode_1xHMMA`）表现出显著的耗时下降**：
     - 在 `P1` 基础上保持 SWAR 打包，将每个 FP8 K32 改写站点的 `2 × HMMA.16816` 减为 `1 × HMMA.16816`（38 个活跃核静态 `HMMA` 从 `13,412` 降至 `6,724`；注：本轮 `P3` 脚本对 `mapped` 源使用了 `lop3.b32 t, low, high, low, 0x96` 即等价于 `high` 且提前合并，改变了 `low` 的依赖保持与生命周期，因此定性为“去 decode 条件下的单拍替代计算探针”，而非严格保留双源的单变量实验），未插桩四轮均值较 `P1` 下降 **`1.393 ms`（720p：`5.329 → 3.936 ms`）/ `2.168 ms`（900p：`7.738 → 5.570 ms`）/ `2.729 ms`（1080p：`10.137 → 7.408 ms`）**（NVAPI 核内合计下降 `1.405 / 1.950 / 2.517 ms`）。

3. **后续可探索的优化方向诊断**：
   上述正交消融表明，虽然单纯调整 `.maxnreg`（`V2.8`）已无全档收益，但在代码生成层仍有两个具备实测敏感度的研究方向（其可兑现比例取决于能否在不破坏数值精度与同步语义的前提下实现）：
   - **方向 A（针对 `V2.7 − P0` 的 `0.41 ~ 0.57 ms` 敏感度）**：研究能否在保持 E4M3 舍入/饱和语义的前提下，进一步压缩 `v22/codegen.py` 中 20 条 PTX 指令 + 5 个临时寄存器的 `FP16x2 → FP8x2` SWAR 打包序列（特别是在 720p 第一大模块 `FB05 ViT` 和存在 spill 的 `FB01 C64` 中）。
   - **方向 B（针对 `V2.7 − P1` 的 `0.58 ~ 1.54 ms` 敏感度）**：研究能否在不引发额外 spill 或跨屏障语义错误的前提下，缩减 `FB01~FB05` 中非 `mapped` 解码临时寄存器池（56~112 个 `.b32`）的同时存活峰值或解码指令数。

### 4.3 `V2.8` 容量波次模型边界（基于 `v28/audit.json`）

在 `V2.8` 的 10 项 `.maxnreg` 压降实验中，CUDA Occupancy API 查询的理论每 SM 驻留块数（`resident_CTA_per_SM`）与理想容量波次（`ceil(Grid_CTAs / (48 * resident_CTA_per_SM))`）显示：
- **`FB05 (ViT)`**（128 线程/CTA = 4 Warps/CTA）：720p 下每次发射 Grid 为 `96 CTA`，在基线 `2 CTA/SM`（`8 Warps/SM`，全卡容量 `96 CTA`）与压 cap 后的 `3 CTA/SM`（`12 Warps/SM`，全卡容量 `144 CTA`）下，理想容量波次均为 **`1` 波**；1080p 下 Grid 为 `160 CTA`，在 `2 CTA/SM`（容量 `96`）与 `3 CTA/SM`（容量 `144`）下离散理想容量波次均为 **`2` 波**。因此抬高单 SM 理论驻留上限并未减少理想容量波次，同时引入了 `64~168 B STACK`（或改变了零 spill 核的寄存器分配），这与 `vit_contract / vit_cq / vit_cqe` 在实测中无净收益或回退的现象相容。
- **`FB04 (C512)`**：`final_head`（256 线程 = 8 Warps/CTA）在 720p/1080p 下 Grid 仅 `24 / 48 CTA`，基线 `1 CTA/SM` 理想容量波次已为 **`1` 波**；`pool` 与 3 个 128 线程 `ffwd` 核在 720p 下 Grid 为 `36 CTA`（基线 `2 CTA/SM` 理想波次为 `1` 波），仅 `proj_512`（256 线程，1080p `80 CTA`）在 `1 → 2 CTA/SM` 时理想容量波次从 `2` 波降至 `1` 波（实测 900p/1080p 微快 `+0.202% / +0.037%`，伴随 `128 B STACK`，未形成显著整帧全档收益）。
