## 一、 核心结论与当前性能发挥定性

### 1.1 `PTX V2.9_fast` 已兑现的收益与画质边界
1. **指令与静态代码缩减**：`PTX V2.9_fast` 采用 9 条核心 SASS 的 Unified Mul Pack（`mul.rn.f16x2 0x1c001c00` 统一 E4M3 Normal/Subnormal 指数对齐 + `lop3 0xd8` + `prmt 0x4431` 高字节拼符号，声明 2 个 `.b32` 临时寄存器），替换了 `V2.2~V2.7` 使用的 13 条核心 SASS SWAR Pack（声明 5 个 `.b32` 临时寄存器）。在 `FB00..FB06` 全部 **38 个实际发射活跃核** 中，非 NOP 静态 SASS 指令从 `175,685` 条降至 **`163,944` 条（净减 `11,741` 条，`-6.68%`）**；按含固定尾部 NOP 的 `v29/audit.py` 口径则从 `176,431` 条降至 **`164,659` 条（净减 `11,772` 条，`-6.67%`）**。
2. **双版本同轮配对提速（`v29/README.md` 99 次运行：其中 `V2.7` vs `V2.9_fast` 专门正式对照为两轮共 48 次进程运行）**：在 `V2.7` 与 `V2.9_fast` 的两轮（`first` + `repeat`）三档分辨率正反 ABBA/BAAB 对照中，`V2.9_fast` 在 **全部 12 个正反方向上方向一致为正**：
   - **第 1 轮（`first`）**：720p `6.02850 → 5.87400 ms`（**`-2.563%`**）、900p `8.83450 → 8.58125 ms`（**`-2.867%`**）、1080p `11.64550 → 11.28750 ms`（**`-3.074%`**）；
   - **第 2 轮（`repeat`）**：720p `6.05300 → 5.89575 ms`（**`-2.598%`**）、900p `8.90400 → 8.72575 ms`（**`-2.002%`**）、1080p `11.59850 → 11.39450 ms`（**`-1.759%`**）；
   - **两轮 8 进程合并均值**：720p **`6.04075 → 5.88488 ms (-2.580%)`**、900p **`8.86925 → 8.65350 ms (-2.433%)`**、1080p **`11.62200 → 11.34100 ms (-2.418%)`**。
3. **画质与数值边界**：在全部 65,536 个 `uint16` 位型中，`V2.9_fast` 有 `65,496` 个（`99.939%`）与 `V2.7` 逐位一致，仅 40 个深层 subnormal 边界码点（正负各 20 个，对应原值 `< 2^-6` 的假 tie 边界）在 E4M3 量化输出码点上相差 1 ULP（详见 `v29/primitives.json`）。整网相对 `V2.7` 的 PSNR 为 **`62.609 / 62.117 / 60.595 dB`**（`maxabs` `0.004395 / 0.005615 / 0.007446`），全部运行 `nonfinite = 0`，720p 天空测试 `变号 = 0`。

### 1.2 站在 `PTX V2.9_fast` 新基线上的正交敏感度结论
本轮我们以 **`V2.9_fast`** 为新原点，构建了破坏性诊断探针 `P0_ZeroPack`（将 pack 替换为单条 `cvt.u16.u32`）、`P1_V29_ZeroDecode`（保持 `V2.9_fast` 的 9-SASS pack，仅旁路 non-mapped 8 指令解码与 `vlh_t` 临时池）及 `P2_Both`（同时应用 `P0` 与 `P1`），连同旧基线 `V2.7` 进行了五版本正反序对照（60 次未插桩 + 30 次 NVAPI 捕获），得出以下两项结论：

1. **结论一：当前已实现的 `V2.9_fast` 稳定兑现了约 `2% ~ 3%` 整帧收益；在 `V2.9_fast` 上仍存在一定幅度的破坏性去 Pack 敏感度（未插桩 `0.298 ~ 0.387 ms`），且与去 Decode 之间存在强负交互**。
   - **未插桩与 NVAPI 两个计时域的完整表现**：在未插桩四轮对照中，`V2.9_fast − P0` 为 **`+0.344250 ms (5.83%)` / `+0.297500 ms (3.43%)` / `+0.387000 ms (3.28%)`**（三档 12 个 pass 方向全部为正）；在 NVAPI 逐核捕获中，`V2.9_fast − P0` 三档核内合计分别为 **`+0.267188 / +0.544947 / +0.173850 ms`**（其中 `FB05 ViT` 三档差值分别为 `+0.122803 / +0.143001 / +0.026394 ms`）。
   - **去 Decode 条件下的负效应（强交互项）**：当在 `P1_V29_ZeroDecode`（已移除 non-mapped 解码）的基础上继续将 9-SASS Pack 替换为单条 `cvt.u16.u32`（`P1_V29 → P2_Both`）时，三档分辨率全部 12 个未插桩 pass 与全部 6 个 NVAPI pass（18/18）方向一致为负：未插桩 `P1_V29 − P2` 为 **`-0.080000 / -0.309250 / -0.780250 ms`**（交互项为 `-0.424250 / -0.606750 / -1.167250 ms`）。这说明 `Pack` 与 `Decode` 的敏感度不可简单相加，不排除后续继续改进 Pack，但当前以敏感度幅度更大的 `Decode` 作为第一优先级。

2. **结论二：在 `V2.9_fast` 基线上，移除 `Non-mapped Decode` 与解码临时池（`V2.9_fast − P1_V29`）方向一致且幅度最大（未插桩 `0.648 ~ 1.732 ms`），是下一轮优化的首选攻坚方向**。
   - 在 `V2.9_fast` 基线上单变量移除 non-mapped 解码与 `vlh_t` 临时池（`V2.9_fast → P1_V29`），在**全部 12 个未插桩 pass 与全部 6 个 NVAPI pass（18/18）上方向一致为正**：
     - **未插桩四轮均值**：720p 下降 **`0.648250 ms (-10.97%)`**（`5.909750 → 5.261500 ms`）、900p 下降 **`1.105500 ms (-12.74%)`**（`8.675250 → 7.569750 ms`）、1080p 下降 **`1.732250 ms (-14.70%)`**（`11.787750 → 10.055500 ms`）；
     - **NVAPI 82 核合计**：720p 下降 **`0.598400 ms (-10.12%)`**、900p 下降 **`1.261133 ms (-14.24%)`**、1080p 下降 **`1.199770 ms (-10.70%)`**。

## 三、 吸收审核意见后的下一刀（`PTX V3.0`）突破口：K-Step 解交错 + B/A-Stationary 无冒险拓扑重排

根据 [1506 审核意见](性能评估20261028-1506-审核意见.md) 第 3、4 节的提示，我们核查了 `v27/source-audit.json` 中峰值 `mma_run` 的操作数复用频次，发现了一个关键事实与直接突破口：

### 3.1 为什么峰值 `mma_run` 会有 `56 / 112 / 80` 个 `.b32` 临时寄存器？
- 在 `FB01~FB05` 的峰值 `mma_run` 中，**不存在 `uses == 1` 的单次操作数**（`FB01~03` 峰值处为 24 对使用 4 次 + 4 对使用 12 次 = 28 对 / `56` 个 `.b32`；`FB04` 峰值处为 48 对 + 8 对 = 56 对 / `112` 个 `.b32`；`FB05` 峰值处为 32 对 + 8 对 = 40 对 / `80` 个 `.b32`）。
- 造成 `56 ~ 112` 个 `.b32` 同时存活的真正原因有两个：
  1. **A-Stationary 遍历顺序**：以 `FB01`（48 条独立 `mma`：4 组 `A_i` × 12 组 `B_j`，48 对互不相交的输出寄存器 `d`）为例，原版 PTX 按外层遍历 4 组 A（16 个寄存器）、内层遍历 12 组 B（24 个寄存器）排列，导致在前 12 条 `mma` 中就把全部 12 组 B 解码为 **`48` 个 `.b32` 临时寄存器** 并保活至第 48 条 `mma`（加上当前 1 组 A 的 `8` 个 `.b32` = **`56` 个 `.b32`**）。
  2. **双 K 步交错排列（K-Step Interleaving）**：在 `FB04`（64/96 条 `mma`）与 `FB05`（64 条 `mma`）中，每条输出链由 2 条串联 `mma`（`k_step = 0` 写入独立临时寄存器对，`k_step = 1` 读取该临时寄存器对累加写回）组成，共计 32 或 48 条互不相交的长度为 2 的独立链。原版 PTX 将 `k_step = 0` 与 `k_step = 1` 交错排列，迫使两个 K 步的全部 B 操作数同时存活，将池峰值翻倍推高至 `80 ~ 112` 个 `.b32`。

### 3.2 解决方案与 `ptxas O4` 静态资源初测：保序拓扑重排（含 `mapped` 隐式依赖与固定入口）
- **算法与安全约束定义（源码见 [eval_20261028_reorder_audit.py](eval_20261028_reorder_audit.py)）**：
  1. **固定原 run 入口映射**：以重排前原始首条指令位置 `orig_start = matches[0].start()` 调用 `mapped_at(packed_sources, orig_start)`，确保重排前后 `mapped` 资格集合、`encoded_operands` 解码次数与 `backup_moves == 0` 严格不变。
  2. **覆盖 `mapped` 隐式 `(low, high)` 源的依赖图**：对每条指令构造扩展读写集合 `expanded_rw(m, mapped)`（除字面 `a0..a3, b0..b1, c0..c1, d0..d1` 外，对所有 `r in mapped` 将其隐式读取的 `mapped[r][0], mapped[r][1]` 纳入读取集合），提取读写冲突连通分量（长度为 1 或 2 的累加链 `chains`），仅在 `has_hazard(matches, order, mapped) == False`（所有存在共有寄存器读写关系的指令对保持原有先后顺序）时允许重排。
  3. **按链步（Step）解交错 + B/A-Stationary 分组选择**：依次排列各链的 `step = 0, 1, ...`，并在每步内比较按 `(b0, b1)` 分组与按 `(a0, a1, a2, a3)` 分组后的实际 `temporary_b32_peak`，仅当峰值严格小于原顺序时采纳（定性为“保序重排候选、静态资源初测”，整网 `0 bit-diff` 与实机帧耗时收益须待后续 GPU 单算子与整网 ABBA 实测验证）。
