## 一、 评估目标与方法论修正

在吸收 [0724 审核意见](性能评估20261029-0724-审核意见.md) 后，本修订版修正了初稿中的指令常数笔误（`v26` 解码乘 $2^8$ 常数为 `0x5c005c00`）、单次打包元素宽度描述（`v29` 每次 9-SASS pack 将 1 个 `.b32` 中的 **2 个 FP16** 转换为 1 个 `.b16` 中的 **2 个 E4M3**），撤回了跨轮次拼凑的四层估算表，并顺着审核意见第 3 条（*“零 spill 核仍有寄存器压力：减少 REG 可提高驻留”*），将 `1506` 实验 JSON 的逐核计时、`by_kernel` 静态资源与 `v23/profile.json` 的真实 `block / shared` 发射参数联立，完成了 **38 个活跃 FP8 核的 G1 / G2 / G3 互斥三分法实测归因**。

## 二、 静态事件账本与 `P1_V29_NoDec` / `P0_ZeroPack` 探针边界

### 2.1 38 个活跃 FP8 核的 PTX 解码事件数 vs 静态 SASS 净差
根据 [v27/source-audit.json](../ptx-patcher/v27/source-audit.json) 与 [v27/source-results.md](../ptx-patcher/v27/source-results.md)，在 `FB00..FB06` 全部 **38 个实际发射活跃核** 中：
1. **`mapped_static_run_events`（同 run 已直连免解码事件）**：共 **`3,524` 次**（直接使用前序打包前的原始 FP16 `.b32` 寄存器对 `(low, high)` 喂给 `HMMA.16816.F16`，生成 0 条解码指令）。
2. **`nonmapped_static_run_events`（非 `mapped` 静态解码事件）**：共 **`5,848` 次**。其 CFG 可达定义来源包括 `global_load`、`shared_load`、`constant_or_special+global_load` 以及部分 `global_load+local_FP8_quantization` 混合路径（`FB00` 128 项、`FB05` 16 项）与被当前 `multidef` 规则拒绝的跨路径项。
3. **当前非 `mapped` 解码生成器（`v26/codegen.py`）的指令构成**：
   每个非 `mapped` 事件将一个含 4 个 E4M3 字节的 `.b32` 寄存器解包为两个含 `f16x2` 的 `.b32` 寄存器（`lo` 与 `hi`），每路生成 **4 条 PTX 指令**：
   - `prmt.b32`（抽取两个字节并对齐到 16-bit 槽位）
   - `and.b32`（分离符号位与 7-bit 指数尾数，编译为 SASS `LOP3.LUT`）
   - `shl.b32`（左移对齐至 FP16 位域，编译为 SASS `SHF.L`）
   - `mul.rn.f16x2 ..., scale`（其中 `scale` 寄存器载入 **`0x5c005c00`**，即两个 FP16 的 $2^8 = 256.0$，恢复指数偏置差 `15 - 7 = 8` 并将 E4M3 subnormal 线性还原为 FP16 normal，编译为 SASS `HMUL2`）
   两路合计 **8 条 PTX 指令**。因此，在 38 个活跃核中，按源事件展开的解码 PTX 指令总数为：
   $$5,848 \times 8 = \mathbf{46,784\text{ 条 PTX 指令}}$$
4. **编译后的静态 SASS 净差对照（不同编译层级的对应关系）**：
   当 `P1_V29_NoDec` 旁路上述 `5,848` 次非 `mapped` 解码及 `vlh_t` 临时寄存器池后，经 `ptxas -O4` 编译，38 个活跃核的总非 NOP 静态 SASS 指令数从 `163,944` 条降至 `117,968` 条，**总静态 SASS 净减少 `45,976` 条**（含尾部 NOP 则为 `164,659 → 118,671`，净减少 `45,988` 条）。由于 `ptxas` 存在指令合并、常量折叠、spill 消除（净减 `70 STL + 76 LDL = 146` 条）及局部循环展开变化（如 `FB03` 静态 `HMMA` 增加 `224` 条），`46,784` 条源级解码 PTX 与 `45,976` 条目标级非 NOP SASS 净差处于不同编译层，不能直接宣称逐条一一对应，但证实了 `P1_V29_NoDec` 静态代码缩减的量级主体来自这 `5,848` 个解码站点。

### 2.2 当前打包生成器（`v29/codegen.py`）的指令构成
- 单次 `cvt.rn.satfinite.e4m3x2.f16x2` 转换接受 **1 个 `.b32` 寄存器（含 2 个 FP16）**，输出 **1 个 `.b16` 寄存器（含 2 个 E4M3）**。
- `PTX V2.9_fast` 使用 **9 条核心 SASS**（声明 2 个 `.b32` 临时寄存器）完成这一对元素的转换：`abs.f16x2` 去符号 → `min.f16x2`（`0x5f005f00 = 448.0` 饱和截断）→ `mul.rn.f16x2`（`0x1c001c00 = 2^-8`，统一对齐 Normal 与 Subnormal 尾数）→ `shl.b32 1 + add.u32 0x007e007e`（编译为 `LEA` 实现偶数舍入进位）→ `lop3.b32 ..., 0xd8`（拼回原符号位）→ `prmt.b32 ..., 0x4431`（抽取两路高字节）→ `cvt.u16.u32` 写出 `.b16`。
- 在 `1506` 同轮五版本正交测试中，在 `V2.9_fast` 基线上将上述 9-SASS Pack 破坏性替换为单条 `cvt.u16.u32`（`P0_ZeroPack`），未插桩四轮均值快 **`+0.344250 ms (5.83%)` / `+0.297500 ms (3.43%)` / `+0.387000 ms (3.28%)`**（NVAPI 82 核合计快 `+0.267188 / +0.544947 / +0.173850 ms`）；而在已移除解码的 `P1_V29_NoDec` 上再移除 Pack（`P1_V29 → P2_Both`）则三档 18/18 全部变慢（未插桩 `-0.080000 / -0.309250 / -0.780250 ms`），显示 `Pack` 与 `Decode` 存在强负交互，二者敏感度不可相加。

## 三、 38 个活跃 FP8 核的 G1 / G2 / G3 互斥三分法实测分析（核心新发现）

为了严格回答“在 `V2.9_fast → P1_V29_NoDec` 的核内净节省（NVAPI 38 个 FP8 核合计 `0.596147 / 1.258701 / 1.201203 ms`）中，静态 Spill 减少、无 Spill 核的 SM 驻留台阶（Occupancy）跃升、以及驻留与 Spill 均不变核的净敏感度各自占多少”，我们结合 [v23/profile.json](../ptx-patcher/v23/profile.json) 的真实发射配置（`blockDim` 线程数与 `dynamic_shared`）及 `sm_86` 硬件规范（每 SM `65,536` 个 32-bit 寄存器、按 `256 regs/warp` 粒度分配、最大 `48 warps/SM`、最大 `16 CTAs/SM`、最大 `102,400 B` Shared Memory/SM），将 38 个活跃 FP8 核划分为三个**完全互斥**的集合：

1. **G1 组（22 个核：静态 `STL/LDL/STACK` 变化为 0，且 `sm_86` 理论驻留 `Active CTA/SM` 变化也为 0）**：
   - 包含 `FB00` 4 核、`FB02` 全部 4 核、`FB03` 全部 4 核、`FB04` 5 核、`FB05` 3 核、`FB06` 全部 2 核（其中 21 个核在 `V2.9_fast` 与 `P1_V29` 下均为 `0 STL / 0 LDL / 0 B STACK`，仅 `FB00` 的 `ds_wait` 恒为 `1 STL / 1 LDL / 8 B STACK`；且全部 22 个核在 `V2.9_fast` 与 `P1_V29` 下的每 SM 驻留 CTA 数与 Warp 数完全相同）。
2. **G2 组（10 个核：静态 `STL/LDL/STACK` 恒为 `0/0/0B`，但因 `REG` 下降跨过 `168 regs` 或 `128 regs` 台阶，使每 SM 理论驻留 `Active CTA/SM` 跃升）**：
   - 在 `sm_86` 上，对于 `128` 线程（`4 Warps/CTA`）的核，当 `REG <= 168` 时每 SM 可驻留 **`3 CTA (12 Warps)`**，一旦 `REG >= 169` 则跌落至 **`2 CTA (8 Warps)`**；当 `REG <= 128` 时可驻留 **`4 CTA (16 Warps)`**。对于 `256` 线程（`8 Warps/CTA`）的核，当 `REG <= 128` 时可驻留 **`2 CTA (16 Warps)`**，一旦 `REG >= 129` 则跌落至 **`1 CTA (8 Warps)`**。
   - 核查发现，`FB05 (ViT)` 的 **6 个零 Spill 主力核** 与 `FB04` 的 **3 个零 Spill 核**、以及 `FB00` 的 **1 个零 Spill 核** 在 `V2.9_fast` 下恰好卡在驻留台阶上方 `4 ~ 29` 个寄存器处，而在 `P1_V29_NoDec` 下全部跨过台阶实现了驻留跃升！
3. **G3 组（6 个核：发生静态 `STL/LDL/STACK` 下降）**：
   - 包含 `FB00` 的 `outview_wait`（`4/4 → 0/0`）、`FB01` 全部 4 个核（合计 `64/70 → 5/5`）及 `FB04` 的 `qkv_512`（`40/29 → 33/22`）。

### 3.3 从三分法得出的四条硬核结论

1. **静态 Spill 下降核组（G3，6 个核）的净敏感度占比仅为 `14.59% ~ 24.55%`（`0.146 ~ 0.212 ms`）**：
   75.45% ~ 85.41% 的核内去 Decode 净节省发生在静态 `STL/LDL/STACK` 完全未变的 32 个核（G1 + G2）中。因此，“通过减少静态 spill 指令即可解释或兑现 `P1` 绝大部分收益”的假设被直接证伪；这也是 `PTX V3.0` 仅削减部分 spill 与临时池峰值却未能取得三档稳定净提速的根本原因。
2. **首次锁定“静态 Spill 與理论驻留均不变”的基准敏感度（G1，22 个核）**：
   即使彻底剔除所有发生静态 Spill 变化的核（G3）以及所有发生理论 `Active CTA/SM` 驻留台阶跃升的核（G2），剩下的 **22 个既无 Spill 变化、也无驻留台阶变化的核（G1）** 依然在 720p / 900p / 1080p 上贡献了 **`+0.452 ms (75.84%)` / `+0.631 ms (50.16%)` / `+0.484 ms (40.28%)`** 的稳定正节省（对应删去 `25,794` 条非 NOP SASS）。这部分收益直接反映了在不改变 SM 驻留台阶与静态栈溢出的前提下，移除非 `mapped` 解码算术、缩短依赖链与释放核内局部寄存器生命周期所带来的净敏感度。
3. **揭示了 900p / 1080p 下 `FB05 (ViT)` 高敏感度的结构性成因（G2，10 个核）**：
   在 900p 和 1080p 高分辨率下，G2 组的 10 个零 Spill 核贡献了 **`+0.415 ms (32.98%)` 和 `+0.542 ms (45.13%)`** 的巨幅节省（其中仅 `FB05` 的 `ffn_contract_chained` 和 `ffn_expand_chained` 两个核在 1080p 上就占了 `0.401 ms / 33.37%`，在 900p 上占了 `0.248 ms / 19.74%`）。
   这两个核在 `V2.9_fast` 下均为 `0 Spill`，但物理寄存器分别为 `179 regs` 和 `180 regs`——**距离 `168 regs` 的 `3 CTA/SM (12 Warps/SM)` 硬件驻留台阶仅超出 `11 ~ 12` 个寄存器**（`ffn_expand_publish` `172 regs` 仅超出 `4` 个寄存器）；`P1_V29` 移除解码后，它们的寄存器降至 `144 ~ 155 regs`，在消除解码指令的同时跨过了 `2 CTA → 3 CTA`（驻留 Warp 数 `+50%`）的硬件台阶。而昨日实验的 `PTX V3.0` 重排在这几个 `FB05` 核上编译出的寄存器仍为 `174 ~ 180 regs`，未能跨过 `168 regs` 台阶。
4. **工程收官定论与后续若重启探索的精确靶点**：
   - **当前阶段收官决策**：`PTX V2.9_fast` 已通过两轮 48 次同轮正反配对验证，稳定兑现 `-2.42% ~ -2.58%` 整帧提速且画质 PSNR `> 60.5 dB`，正式作为当前生产推荐版本收官。
