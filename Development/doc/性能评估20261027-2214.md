## 三、GPU 硬件原子计数器实测的动态循环账本（修正早期静态 Roofline 盲区）

在早期的粗略 Roofline 估算中，直接用正则表达式在 PTX 文本里统计静态 `mma.sync` 行数，漏掉了三个真实的运行期物理事实：
1. **`FB04 (C512)` 和 `FB05 (ViT)` 的矩阵乘位于 `for` 循环体内**（静态文本仅出现 1 次的 `HMMA` 块在运行期会循环迭代 **5 ～ 16 圈**）；
2. **第一层 `FB00 (C32)` 存在边界取整扩边**（720p 实跑 `1344×768` 多算 **12.0%**，1080p 实跑 `1920×1152` 多算 **6.7%**）；
3. **重型首尾核 `pre_block / post_block` 的每 Warp `HMMA` 数为 `528 / 580` 条**（高于普通 C32 核的 `512` 条）。

## 四、`PTX V2.3 → V2.5` 深度消融与收敛边界总结

在 `V2.3` 至 `V2.5` 期间，我们完成了超过 **340 次** 严格受控的消融实验，探明了当前 PTX 改写路线的全部边界：

1. **按需交错解包 + 死亡操作数寄存器池复用（`V2.4` 采纳，净赢 `0.4% ~ 1.5%`）**：
   - 将 `mma_run` 从“入口一次性解包全部 64～160 个 `.b32` 临时寄存器”改为“按首次使用即时解包 + 末次使用后归还临时寄存器池（含累加器覆写前别名保护）”，临时 `.b32` 声明峰值下降 **30% ～ 86%**（`FB04` `160→112`、`FB05` `128→80`、`FB00` `64→40`、`FB06` `144→20`），258 次运行 100% 严格 `0 bit-diff`。
2. **为什么“偶 `PRMT` + 奇 `LOP3`（`V2.5` Hybrid8）”慢于对称双 `PRMT8`（`V2.4`）？**
   - 实测全网三档慢 `+0.41% / +1.31% / +2.09%`。SASS 审计揭示：奇半边去掉 `PRMT + IMAD.SHL` 后引入的 `shr.u32 ..., 1` 被编译为 `5,712` 条 `SHF.R.U32.HI`（漏斗移位）；而在 Ampere `sm_86` 中，**`SHF` 与 `PRMT` 共用同一个低吞吐移位/置换子单元**，而原 `PRMT8` 中的左移被编译为走整数乘加管道的 `IMAD.SHL.U32`。因此对称双 `PRMT8` 反而实现了更好的跨管道分流。
3. **为什么 `.maxnreg` 的 `hot255`（`FB00/03/04/05/06=255, FB01/02=168`）已是全局帕累托最优？**
   - 12 组单 FB 对照 + 16 次 NVAPI 逐核计时证明：`FB01 (C64)` 放宽至 `192/224/255` 虽能清零 192B spill，但每 SM 最大驻留从 `12 Warps` 跌至 `8 Warps`，导致 `FB01` 从 `1.221 ms` 退化至 `1.316 ms`；反之将 `FB04 / FB05` 压回 `168` 虽能提高理论驻留，却引发 `640 B / 176 B` 栈溢出，导致耗时暴涨 `+4.2% ~ +6.7%`。
4. **为什么 `tilesync / wait` 跨块同步不能直接删除？**
   - 绕过就绪轮询与 `fence.acq_rel.gpu` 会导致同 Stage 内 `inpview_tilesync` 与 `ds_wait` 的生产者-消费者依赖破裂（画面崩至 `15 ~ 24 dB`）；仅移除 `nanosleep` 保留轮询则耗时无变化（`0.00 ms` 收益）。
5. **为什么细碎 PTX 算术变形（如 `+0x603f603f` 偏置合并、独立 `FP8_UP` 7→5）不再产生显著帧收益？**
   - 40 个活跃 Kernel 的 SASS 审计表明，`ptxas -O4` 后端的常量折叠已自动吸收了移位前后的常数加法（40 个活跃核静态 SASS 总条数 **0 变化**）；而 `FP8_UP` 位于循环外，非热点路径。
