## 二、NVAPI 82 次发射真实结构与 `V2.2` 基线逐 Fatbin 耗时账本

在 `V2.3` 阶段，通过 MinHook 拦截 `nvapi_QueryInterface` 解析出的 `NvAPI_D3D12_CreateCuModule / CreateCuFunction / LaunchCuKernelChain`，并在每次发射前后插入 D3D12 硬件时间戳（50 warmup / 20 iter），对 **`V2.2` 基线 DLL** 进行了逐核捕获（详见 [v23/kernel-ledger.md](../ptx-patcher/v23/kernel-ledger.md)、[v23/profile.json](../ptx-patcher/v23/profile.json)）。

- **发射结构**：稳态每帧固定发射 **82 次**（**40 个唯一 Kernel 名**，每次链含 1 个核），`FB07 ~ FB12` 未发射。
- **区间空隙边界**：插桩 GPU 时间戳区间之间的 gap 之和 median 为 **`0.0215 ms`（720p）/ `0.0241 ms`（1080p）**，表明在该捕获中未观察到数毫秒级的核间空洞（注：每个测量区间内部仍可能包含 dispatch-local 开销，且时间戳插桩本身会扰动调度，故正式提速结论只使用未插桩 `bench_sky.exe`）。

## 三、`FB00 / FB04 / FB05` 软件插桩实测的 MMA 语义工作量与计算循环圈数

在 `PTX V2.5` 阶段，我们向诊断用 `V2.4` DLL 的 `FB00 / FB04 / FB05` 内核追加了独立 UAV 指针参数（由收敛 MMA run 的 `lane 0` 执行原子累加，三档输出与未插桩参考保持 `0 bit-diff`，发射 Grid/Block 序列与第 50 帧一致；详见 [v25/README.md](../ptx-patcher/v25/README.md)、[v25/dynamic-ledger.md](../ptx-patcher/v25/dynamic-ledger.md)、[v25/dynamic-ledger.json](../ptx-patcher/v25/dynamic-ledger.json)）。

> **四个证据等级的严格区分**：
> 1. **软件插桩实测的 MMA 语义等价次数与自然计算循环访问次数**：仅直接覆盖 `FB00 / FB04 / FB05`（按 1 条 FP8 K32 换算 2 条 `HMMA.16816`、原生 FP16 K16 按 1 条计）；
> 2. **解包代码生成器的动态 PTX 事件数**：插桩记录的 PTX 级 `PRMT`/整数/半精度解包事件（后续会被 `ptxas -O4` 优化重排，不等于最终 SASS 动态发射数）；
> 3. **计算循环展开的辅助 SASS 模型（`FB04 / FB05`）**：基于 `V2.4` SASS CFG，将自然计算循环按实测访问次数展开、循环外按发射 warp 计 1 次、条件分支取可达并集（**未测量实际谓词分歧、分离 helper 子程序及自旋重试，不是硬件动态指令计数器读数**；`FB00` 在该模型中标为 `not modeled`）；
> 4. **硬件性能计数器（Issued / Pipe Utilization / Stall）**：本轮未采集。

## 四、`PTX V2.3 → V2.5` 消融实验记录（共 342 次运行）

在 `V2.3`（38 次）、`V2.4`（258 次）、`V2.5`（46 次）合计 **342 次运行（30 次初验 + 312 次 50 warmup / 80 iter 正式运行）** 中，已测试方案的结论与边界如下：

1. **按需交错解包 + 死亡操作数寄存器池复用（`V2.4` 唯一默认启用项，`mask=8`）**：
   - 按操作数首次使用位置即时解包、末次使用后归还临时寄存器对（若源寄存器或 `mapped` 别名会被更早的 MMA 累加器覆写，则提前在首次覆写前保存），将各 FB 的临时 `.b32` 声明峰值压降 **30% ～ 86%**（`FB00` `64→40`、`FB01/02` `80→56`、`FB03` `96→56`、`FB04` `160→112`、`FB05` `128→80`、`FB06` `144→20`）。
   - 注意虚拟声明峰值下降不等于硬件物理零 spill：在 `V2.4` 全导出审计中，`FB01` 最大 `STACK` 为 `192→224 B`（`LDL+STL` `477→507`），`FB04` 为 `96→88 B`（`LDL+STL` `125→127`），`FB05` 为 `16 B`，其余为 `0`（[v24/resources.json](../ptx-patcher/v24/resources.json)）。但因同轮正反 ABBA 三档 median 均值皆优于 `V2.3`（`-0.768% / -0.403% / -1.479%`），故采纳为 `V2.4` 推荐配置。
2. **奇半边 `LOP3 + SHR` 分流（`V2.5` `Hybrid8` 负结果，未采纳）**：
   - 将非 `mapped` 解包的奇半边从 `PRMT 0xb391 + AND + SHL` 改为 `AND 0x7f007f00 + SHR 1 + LOP3 0xea`。在 `FB00`（1080p）中，由于非 `mapped` 对仅占 `12,892,128 / 43,001,348 ≈ 29.98%`（其余 `70.02%` 为 `mapped` 的 `0x5410/0x7632`），整个 MMA 解包 PTX `PRMT` 事件仅下降 `14.99%`。
   - 在 40 个活跃核的静态 SASS 中，`PRMT` 从 `25,483` 降至 `19,774`（`-5,709`），`IMAD.SHL.U32` 从 `12,169` 降至 `6,456`（`-5,713`），但 `SHF.R.U32.HI` 从 `6,355` 增至 `12,067`（`+5,712`），`LOP3.LUT` 从 `32,370` 增至 `38,081`（`+5,711`），总静态指令从 `183,651` 略增至 `183,800`。
   - 同轮三档正反 ABBA 全网实测均回退（`+0.413% / +1.313% / +2.090%`），仅对 `FB00` 启用在 1080p 下正反向变号无稳定收益；具体是哪项微架构资源竞争、依赖延迟或寄存器分配导致回退，尚需微基准或硬件计数器验证。
3. **12 组单 Fatbin `.maxnreg` 离散台阶对照（基于 `ABC mask=15` 基线，未见更优替换点）**：
   - 对 `FB01 (C64)` 测试 `192 / 224 / 255`：活跃 C64 核最大 `STACK` 从 `168` cap 下的 `216 B` 分别降至 `64 B / 8 B / 0 B`，但 CUDA Occupancy API 计算的理论最大驻留从 **`12 Warps/SM` 降至 `8 Warps/SM`**，1080p 整帧耗时反而变慢（`255` cap 下慢 `+0.759%`）；
   - 对 `FB04` / `FB05` 测试下调至 `168 / 192 / 224`：`168` cap 下活跃最大 `STACK` 分别升至 `640 B / 176 B`，1080p 整帧分别变慢 `+6.723% / +4.219%`（[v24/caps-resources.json](../ptx-patcher/v24/caps-resources.json)）。
   - 因此在本轮已测试的 `ABC` 配置和离散 cap 点中，未发现足够稳定的替换收益，当前继续沿用 `hot255`（`FB00/03/04/05/06=255, FB01/02=168`）。
4. **独立 `FP8_UP`（`A`）、`+0x603f603f` 偏置合并与 `1,688` 对四字节融合打包（`B`）及同步消融**：
   - 经检查原 PTX 与自然循环，40 个活跃核共有 `1,640` 处独立 `FP8_UP`，其中 `0` 处落在已识别自然计算循环内（静态 SASS 减少 `1,878` 条，单因素三档 `+0.069% / -0.221% / +2.283%` 方向不稳定）；
   - `+0x603f603f` 偏置合并后，所审计 40 个活跃核的静态 SASS 每核总条数均未减少（opcode 直方图有局部变化），单因素及配 `1,688` 对合格四字节融合后正反向仍有波动，故 `A`、`B` 均保留代码开关而不默认启用；
   - 同步消融中，同时绕过就绪轮询并删除 `fence.acq_rel.gpu` 会导致输出崩溃至 `15 ~ 24 dB`，证明该组同步操作不可直接删除；仅移除 `nanosleep` 则未测得净收益（`6.1515→6.1520 ms` / `11.6585→11.6695 ms`）。

---

## 五、阶段性收束结论

已验证 PTX 改写路线在固定 `Preset 2`、所测三档输入上将 RTX 3080 Laptop 的 DLSS 5 GPU 耗时从初始 `O1` 的 `30.89 / 47.55 / 67.74 ms` 及 `V1` 的 `15.88 / 24.51 / 31.96 ms` 显著推进至 `V2.3/V2.4` 的 **`~6.1–6.2 / 8.9–9.1 / 11.7–12.0 ms`** 区间，且 `V2.0 → V2.4` 全程保持逐位一致（`0 bit-diff`）。NVAPI 捕获确定了每帧 82 次发射的真实拓扑与 `FB04~06` 的小 Grid 弱缩放；软件插桩补齐了 `FB00 / 04 / 05` 的 MMA 语义工作量与计算循环圈数。`Hybrid8` 与多组单 FB `.maxnreg` 改写均未击败 `V2.4`，约束了当前已测试的局部改写分支；同时，由于尚未采集硬件级动态管道 stall 与真实 issued 指令计数器，我们不将当前结果宣称为全局理论极限。
