## 二、通宵三轮“评估 $\rightarrow$ 审计 $\rightarrow$ 破壁”闭环的核心技术收获

### 1. 第一轮闭环（`V2.5 → V2.6`）：从 `70.02% mapped` 审计数据到消除 `21,712` 条 `PRMT`
- **审计触发点**：在审核 `2214` 报告时，基于 `V2.5` 插桩数据指出 `FB00`（1080p）的 `43,001,348` 个 MMA 解包对中，非 `mapped` 仅占 `29.98%`（`1,289 万`对），而 **`mapped` 占 `70.02%`（`3,011 万`对）**。
- **技术破壁（`PTX V2.6`）**：将线程内 K32 拆解从偶奇 `{byte0,byte2}/{byte1,byte3}` 改为低高半字 `{byte0,byte1}/{byte2,byte3}`。非 `mapped` 改用 `prmt 0x9180 / 0xb3a2` 保持 8 条指令不变；而 **`70.02%` 的 `mapped` 操作数直接填入原生 `(low, high)` 寄存器，实现 0 条 `PRMT`、0 个临时寄存器对直通**（全网消除 `21,712` 条静态 `mapped` PTX `PRMT`，40 活跃核静态 SASS `PRMT` 从 `25,483` 降至 `19,864`，总 SASS 净减 `5,481` 条；`FB01` 全导出最大 `STACK` 从 `224 B` 降至 `104 B`），三档同轮正反 ABBA 净快 **`1.96% / 2.27% / 2.30%`**（720p 首次破入 **`5.980 ms`**，1080p 降至 **`11.463 ms`**）。

### 2. 第二轮闭环（`V2.6 → V2.7`）：从 CUDA Occupancy API 审计到 C32 四核 `8 → 12 Warps/SM` 跃迁
- **审计触发点**：在审核 `0207` 报告时，用 CUDA Occupancy API 纠正了粗略总寄存器除法，查明 `V2.6` 使 `FB00` 中 4 个主力 C32 核（`pre_block`, `inpview_tilesync`, `ds_wait`, `outview_wait`）的物理寄存器从 `231~236` 自然降至 **`196~200`**，但理论驻留仍卡在 `8 Warps/SM`；唯有将其 `.maxnreg` 设为 `168` 才跨越台阶升至 **`12 Warps/SM`（+50% 理论驻留）**，且此时 4 核 `STACK` 仅为 `pre=0, inp=8, ds=8, out=16 B`（而保留仍需 `242 / 212` regs 的 `post_block` 与 `upsample` 为 `255`）。
- **技术破壁（`PTX V2.7`）**：仅对上述 4 个 C32 核启用 `.maxnreg 168`，170 次运行全部相对 `V2.6` **严格 `0 bit-diff`**，三档同轮正反 ABBA 在 `V2.6` 基础上再快 **`0.938% / 0.670% / 0.975%`**！
- **同步完成的底层账本（`V2.7` 阶段）**：
  1. **同轮正反序 NVAPI 逐 FB 新账本（`V2.2` vs `V2.4` vs `V2.6`）**：720p 核区间合计 `6.197 → 6.082 → 6.011 ms`，1080p 核区间合计 `11.919 → 11.674 → 11.446 ms`（其中 `FB00` 在 `V2.4→V2.6` 单步即节省 `0.076 / 0.180 ms`）；
  2. **非 `mapped` 来源 CFG 完整追溯**：查明 `FB01~05` 最大临时池（`56/56/56/112/80` `.b32`）均由 `global_load`（`24~48` 对）与 `shared_load`（`4~8` 对）组成，无同基本块纯 `mov` 重复解包，并修复了定义解析器对 `::` 限定符的识别。

### 3. 第三轮闭环（`V2.7 → V2.8`）：`FB05 / FB04 / FB00` 十项核级驻留控制的实证封顶
- **审计与实验发现（[性能评估20261028-0335-审核意见.md](性能评估20261028-0335-审核意见.md)、[v28/README.md](../ptx-patcher/v28/README.md)）**：
  1. **有限 Grid 波次（Finite Grid Wave Capacity）限制了小 Grid 核提高驻留上限的收益**：
     在 48 个 SM 上，720p 下 ViT 的 `contract / qkv / expand` 每次仅发射 **`96` 个 CTA**，原 `2 CTA/SM`（全卡容量 `96` CTA）已能一锅装完整个 Grid（理想容量波次 `1 → 1`）；`FB04` 的 `final_head` 仅 `24 / 48` CTA（原 `1 CTA/SM` 容量 `48` 已够装完），`proj_pool / ffwd` 仅 `36 / 80` CTA（原 `2 CTA/SM` 容量 `96` 已够装完）。这与 `FB00 (C32)` 拥有 `4,032 ~ 34,945` 个 CTA（数百个波次，提高每 SM 驻留立竿见影）形成了本质区别。
  2. **“仅差 8～13 个寄存器”在编译后仍可能触发可观的 `STACK` 溢出**：
     实测编译证实：虽然 `vit_contract (179→168)` 与 `proj_pool (180→168)` 确实实现了 **`0 B` `STACK`** 并升至 `12 Warps/SM`，但 `final_head (136→128)` 产生了 **`136 B`** `STACK`、`proj_512 (141→128)` 产生了 **`128 B`** `STACK`、`vit_qkv (197→168)` 产生了 **`64 B`** `STACK`、`C32 upsample (212→168)` 产生了 **`56 B`** `STACK`。
  3. **275 次实测裁决**：
     对 10 个单核/分层控制及 `pool + proj + up` 互补组合进行 264 次 50/80 正反 ABBA 正式运行与 11 次快验（全部相对 `V2.7` 严格 `0 bit-diff`）：零 spill 的 `vit_contract` 在 720p 同向慢 `0.882%`；`pool`、`proj`、`up` 单项及组合均存在跨分辨率反号（组合 720p `-0.175%` / 900p `+0.360%` / 1080p `+0.037%`）。遵循“无全档稳定净收益不晋升”的工程纪律，**正式锁定 `PTX V2.7` 为当前最优生产推荐版**。
