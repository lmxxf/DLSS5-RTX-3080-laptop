## 一、 系统边界定义与先核数据总表（De-anchoring 客观账本）

### 1.1 系统工程边界定义
本报告评估的候选搜索定义在以下 **原版 `nvngx_dlssnr.dll` (`v310.9.16.0`) 二进制改造工程边界** 之内：
1. **Host 与模型资产不动**：不重写闭源 Host CPU 调度代码、不改变原版内嵌权重段与 Host-Device 函数参数 ABI、保持稳态每帧 82 次 NVAPI Kernel 发射序列与 Grid/Block 几何尺寸不变；
2. **PE 原槽位 `O4` 约束**：15 个内嵌 Fatbin 编译压缩后装入原 PE 槽位（文件总长恒为 `266,414,592 B`）且全部开启 `ptxas --opt-level=4`；
3. **预设晋升与质量门**：
   - 速度门：候选必须在未插桩 `bench_sky.exe`（720p `sky`、900p/1080p `scene`，每进程 50 warmup / 80 iter，串行正反序 ABBA / BAAB）中，通过 **首轮（`first`）+ 复测确认轮（`repeat`）三档全部正反方向一致净提速**；
   - 质量门：精确改写要求末帧相对同配置 `V3.1_pack5` 严格 `0 bit-diff`（`maxabs = 0, nonfinite = 0`）；近似改写要求相对 `V3.1_pack5` 三档 `PSNR >= 50 dB`、`maxabs <= 1/64`、`nonfinite = 0` 且 720p 天空色带 `变号 = 0`。

## 二、 前四分支实测归因与审稿发现的后续未排除方向

### 2.1 前四分支（33 个命名功能候选）未晋升的实验归因
1. **分支 1（`.maxnreg` 跨阶控制）**：在 `V3.2` 的 6 个 `G2` 临界核单核 cap 控制中，5 个核在压至 `168/128` 后产生 `8 ~ 152 B STACK`；唯一零 Spill 跨阶的 `split_up_pool`（`162 regs, 0 B STACK, 2 → 3 CTA/SM`）其发射网格（720p `36 CTA`、1080p `80 CTA`）小于基线理论单波次容量（`96 CTA`），实测在 900p 负向（`-0.045%`）。
2. **分支 2（通用 `pack5` 与双对 `Quad` 融合）**：`V3.4` 的 `local_quad.py` 通过同基本块最近定义与 CFG 全后继死变量分析证实，在全网 7,540 个 `mov.b32 %dst, {%lo, %hi}` 中，除 `FB01 (456) / FB02 (616) / FB03 (616)` 共 `1,688` 对外，其余 5,852 处新增可融合对数为 `0`。对既有 `1,688` 对测试的 `quad_all`、`quad_fb23`、`quad_fb1` 中，`quad_all` 与 `quad_fb1` 首轮胜出但 `repeat` 确认轮均回退。
3. **分支 3（非直通解码虚拟池与重算控制）**：`V3.3` 的 `phase_pass` 在不增加半片段解码事件（`11,696`）的前提下将 `FB00..06` 虚拟解码池峰值从 `24/56/56/56/112/80/20` 压至 `12/28/28/28/28/28/6`，但连同 `phase_guarded` 及 `remat_spill/fb1/qkv/call` 均未在三档正反 ABBA 中取得全胜。
4. **分支 4（原表示 CFG 转发与 `FB01~03` 整块 Shared 2× FP16 改写）**：
   - `V3.3` 的 144 项 `global_load + local_FP8_quantization` 合流事件与 `V3.4` 的 36 项 `pack_multidef` 事件（该 36 项为 144 项的子集，并集共 144 项）经 CFG 可达定义核实，在到达 `mma_run` 入口时均存在两条不同运行时语义的可达定义，无法作无条件 fallback-native 替换。
   - `V3.5` 的 7 个 `FB01~03` 整模块 Shared 2× 扩容耦合候选（其中 `shadow` 保留原 1× store 并新增 2× 扩展视图使镜像写字节为 3×，`inplace` 在 `FB01` 原位扩为 2×；`fb2_exact_shadow` 在保持 `REG = 168, 3 CTA/SM` 下使 `FB02` 新增 `69/55 STL/LDL`，全网升至 `176/163`）在首轮均未取得三档六方向全胜（注：`fb3_exact_shadow` 在 720p `+0.136%`、1080p `+0.027%` 为正，900p 为 `-0.522%`）。

### 2.2 响应审稿意见第 4 节：立项新分支 5、6、7（`PTX V3.6`）继续实测
依据 [《性能评估20261101-0105》审核意见](性能评估20261101-0105-审核意见.md) 第 4 节指出的三项尚未被实验排除的具体性能缺口，我们不以“阶段资源决策”提前收工，而是将这三项未排除方向正式立为 `K-Search` 的 **分支 5、分支 6、分支 7** 并推进 `PTX V3.6` 构造性实测：
1. **分支 5 `[Open ⚡]`：有界/非负生产者的 Pack 前端特化（`Range-Proven Pack4 / Pack3`）**——审计全网 8,944 处 `cvt.rn.satfinite.e4m3x2.f16x2` 的源寄存器是否已在前序指令中被夹断于 `[-448, +448]`（可省去 `min.f16x2 448` 即 `HMNMX2`，并将 `abs.f16x2` 直接折叠进 `HMUL2 |R|, 2^-8` 形成 **4-SASS Pack**）或非负有界 `[0, 448]`（可再省去符号拼回 `LOP3` 形成 **3-SASS Pack**）；
2. **分支 6 `[Open ⚡]`：`FB02 / FB03` 原位（In-Place）Shared 2× 扩容与按入口/按段零 Spill 精选**——消除 `shadow` 模式的 3× 写端冗余，对 `FB02/03` 实施原位 2× 替换，并按单入口/单存取段筛选不增加 `STL/LDL` 且单档正向的核（如 `FB03`）；
3. **分支 7 `[Open]`：`FB04 / FB05` Shared 阶段与异步拷贝协同耦合审计与改写**——核查并实测 `FB04/05` 中不与 `cp.async` 冲突的纯本地量化 Shared 段，以及 `cp.async` 写入后的分区/协同解包改写。
