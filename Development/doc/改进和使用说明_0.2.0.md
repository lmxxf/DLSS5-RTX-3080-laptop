## 一、`v0.2.0` 核心改进详解（为什么不改文件大小就能再快 2.5 倍？）

先看同一台 **RTX 3080 Laptop（16GB，132W）** 上四个版本的同口径实测数据对比：

| 版本 / 方案（均为 31 层新模型 `Preset 2`） | DLL 体积 | `1280×720` (720p) | `1600×900` (900p) | `1920×1080` (1080p) | 画质（相对原版 PSNR / 天空色带） | 相对网上方案提速 |
| :--- | :---: | :---: | :---: | :---: | :--- | :---: |
| **① 网上开源 `dlssnr-patcher` (`O1`)** | 254 MB | `37.13 ms` | `49.89 ms` | `67.69 ms` | **有 Bug（106 条天空红绿横带）** | `1.00×` |
| **② 我们的首发版 `v0.1.0` (`O4`)** | 254 MB | `15.88 ms` | `24.51 ms` | `31.96 ms` | **100% 原版精度**，0 色带 | `2.12× ~ 2.34×` |
| **③ 社区 510 MB 改版 (`v2i8_255`)** | 510 MB | `6.42 ms` | `9.33 ms` | `12.31 ms` | 混入有损 INT8，PSNR 跌至 **`38.5 dB`** | `5.36× ~ 5.78×` |
| **④ 我们的新版 `v0.2.0` (`PTX V2.1`)** | **254 MB** | **`6.66 ms`** (~150 FPS) | **`9.70 ms`** (~103 FPS) | **`12.78 ms`** (~78 FPS) | **`58.5 ~ 62.5 dB` 无损级精度**，0 色带 | **`5.14× ~ 5.58×`** |

为什么社区那个版本会膨胀到 510 MB 且画质掉到 `38.5 dB`？因为它的作者把 DLL 里的 FP8 权重离线扩成了两倍大的 FP16（254 MB 变 510 MB），还在 `C256` 模块里塞了有损的 INT8 矩阵乘（`IMMA.16832.S8.S8`）。

但当我们用反汇编工具 `cuobjdump` 扒开底层 SASS 机器码后发现，真正让速度从 `32 ms` 降到 `12 ms` 的核心物理机制，其实是下面两刀——而且**这两刀完全不需要扩充 510 MB 权重，也不需要用有损 INT8**：

### 改进 1：矩阵内积交换律与“偶奇 K16 原位拆解”（砍掉全网 94.5% 的跨线程洗牌，立省 11.6 ms）

老黄原版的 `nvngx_dlssnr.dll` 用的是 RTX 40/50 系的硬件 FP8 矩阵指令 `mma.sync.aligned.m16n8k32.f16.e4m3.e4m3.f16`（一次算 **K=32** 个元素）。而 RTX 30 系的 FP16 Tensor Core 指令是 `m16n8k16`（一次算 **K=16** 个元素），所以必须把 1 条 `K=32` 的 FP8 指令拆成 2 条 `K=16` 的 FP16 指令。

在原版指令里，每个线程（`lane`）的 32 位寄存器 `REG` 里装着同一行/列的 4 个 FP8 字节：`{byte0, byte1, byte2, byte3}`。
- **之前的做法（网上脚本与 `v0.1.0`）**：强行按顺序把前 16 个 K（需要跟邻居线程凑 `{byte0, byte1}`）分给第一条指令、后 16 个 K（`{byte2, byte3}`）分给第二条指令。结果每次矩阵乘之前，所有线程都得调用 `shfl.sync` 跟隔壁线程交换数据，再用 `prmt.b32` 重新拼字节！全网 7 个主干代码包里竟然塞了 **81,853 条 `SHFL` 洗牌指令**！
- **`v0.2.0` 的新做法（偶奇 K16 原位拆解）**：
  仔细看就会发现，在矩阵 A 和矩阵 B 中，**同一个线程手里的 `{byte0, byte1, byte2, byte3}` 对应的 K 下标是 100% 一一对应的**！
  既然矩阵内积只认乘积之和、不认先后顺序：
  $$\sum_{k=0}^{31} A_{i,k} B_{k,j} = \underbrace{\sum_{m=0}^{15} A_{i,2m} B_{2m,j}}_{\text{偶数字节对 } \{byte_0, byte_2\}} + \underbrace{\sum_{m=0}^{15} A_{i,2m+1} B_{2m+1,j}}_{\text{奇数字节对 } \{byte_1, byte_3\}}$$
  我们直接让第一条 `m16n8k16` 算每个线程自己寄存器里的**偶数字节对 `{byte0, byte2}`**，第二条 `m16n8k16` 算自己寄存器里的**奇数字节对 `{byte1, byte3}`**！
  更妙的是，在 32 位整数里，`byte0` 在低 16 位的低字节（`bit 0..7`）、`byte2` 在高 16 位的低字节（`bit 16..23`），`byte1` 和 `byte3` 则在高低 16 位的高字节（`bit 8..15` 和 `24..31`）——**它们天生就对齐在 `f16x2` 的两个 16 位通道上**！
  ```ptx
  // 偶数字节对 (byte0, byte2) 原位转 f16x2：0 次 shfl.sync，0 次 prmt.b32！
  and.b32 dlssnr_fp8_abs, REG, 0x007f007f;
  and.b32 dlssnr_fp8_sign, REG, 0x00800080;
  mad.lo.u32 FIRST, dlssnr_fp8_sign, 2, dlssnr_fp8_abs;
  shl.b32 FIRST, FIRST, 7;
  mul.rn.f16x2 FIRST, FIRST, 0x5c005c00;

  // 奇数字节对 (byte1, byte3) 原位转 f16x2：0 次 shfl.sync，0 次 prmt.b32！
  and.b32 dlssnr_fp8_abs, REG, 0x7f007f00;
  and.b32 dlssnr_fp8_sign, REG, 0x80008000;
  shr.u32 dlssnr_fp8_abs, dlssnr_fp8_abs, 1;
  or.b32 SECOND, dlssnr_fp8_abs, dlssnr_fp8_sign;
  mul.rn.f16x2 SECOND, SECOND, 0x5c005c00;
  ```
  仅靠这 10 行代码，全网静态 `SHFL` 指令从 **81,853 条暴跌到 4,517 条（砍掉 94.5%，矩阵乘内部洗牌彻底归零）**，1080p 耗时当场从 `31.96 ms` 降到了 **`20.36 ms`**！

### 改进 2：解开原版 PTX 为 5090 写死的 `.maxnreg 168 / 128` 紧箍咒（消除显存栈溢出，再省 7.6 ms）

为什么从 `20.36 ms` 还能再砍掉将近 8 毫秒到 **`12.78 ms`**？
我们用 `cuobjdump -res-usage` 检查编译后的寄存器与栈内存（`STACK`）时，揪出了第二个大坑：
- 老黄的工程师在给 RTX 5090（`sm_120`）写这套 PTX 时，在主干核函数的头部硬编码写死了编译器寄存器上限 **`.maxnreg 168`**（`FB03` 甚至写死了 **`.maxnreg 128`**）。
- 在拥有硬件原生 FP8 的 RTX 5090 上，4 个 FP8 字节挤在 1 个寄存器里，168 个寄存器绰绰有余。
- 但到了 RTX 30 系（`sm_86`）上，每个 FP8 寄存器都要解包成**偶、奇两个 FP16 寄存器**（寄存器需求翻倍）！此时头顶上的 `.maxnreg 168` 就成了卡死编译器的紧箍咒——编译器看着 169～255 号硬件寄存器空着不准用，被迫把多出来的几十个活跃寄存器统统**溢出（Spill）到了极其缓慢的显存局部栈（Local Memory `STACK`）里**！
  - 比如 `FB04`（`C512` 模块）每个线程溢出了 **`1,032 字节` 显存栈**，单核产生 **4,370 条 `LDL / STL` 显存栈读写指令**；
  - `FB05`（`ViT` 全局注意力）溢出了 **`480 字节` 显存栈**，产生 **2,044 条 `LDL / STL` 栈读写指令**！
- **解法**：我们在 `v0.2.0` 中把存在严重栈溢出的 `FB00 / 03 / 04 / 05 / 06` 五个代码包的 `.maxnreg` 放宽到硬件上限 **`255`**（`FB01 / 02` 保持 `168` 最优）。
  一放开，**`FB00 / 03 / 06` 的显存栈溢出直接归零（`0 B`），`FB04` 和 `FB05` 的显存栈读写指令被砍掉了 97%～99%**！而且因为省掉了几千条 `LDL / STL` 指令，编译出来的 `.cubin` 体积反而更小，**15/15 个代码包依然 100% 原槽位装入 254 MB 的 DLL 中**，输出画面与放宽前 **100% 逐比特一致（`0 bit-diff`）**，耗时直接从 `20.38 ms` 杀到了 **`12.78 ms`（720p 仅 `6.66 ms`）**！

### 改进 3：修复《剑星》转动视角时主角脸部闪烁（默认回归 `1.0 / 1.0` 平衡强度）

为什么在 `v0.1.0` 里玩《剑星》，快速转动镜头时主角的脸会闪一下？
- 这是因为 DLSS 5（神经渲染）内部有一套原生的**运动遮罩（Motion / Control Mask）保护机制**：当镜头静止或缓慢移动时，DLSS 5 满额叠加神经重打光与皮肤细节；当镜头快速甩动时，为防止重影和拖尾，模型会自动降低重打光权重、平滑回退到原始画面。
- 在 `v0.1.0` 中，我们把《剑星》常规包的默认细节迁移强度设成了 `TransferStrength=1.5, ColourStrength=1.1`（比原厂默认的 `1.0` 强行放大了 50%）。结果静止时主角脸部像打了强光浓妆，一转视角回退到原图，1.5 倍与原图之间的巨大反差在肉眼看来就像是“脸部效果丢了闪一下”。
- **在 `v0.2.0` 中**：我们将 `OptiScaler-DLSS5-RTX30-0.2.0.zip` 的默认 `OptiScaler.ini` 改回了原厂平衡的 **`TransferStrength=1.0 / ColourStrength=1.0`**，让运动遮罩过渡自然无闪烁；同时把 `1.5 / 1.1` 的配置单独存为包内的 `OptiScaler-增强风格.ini`，喜欢浓烈风格的朋友可以随时按需替换。

### 改进 4：顺带沉淀了 16 轮优化的独立 CUDA 引擎（`Development/hip-port/`）

除了上面的原版 PTX 改写路线（路线 B，`v0.2.0` 发布包所用），这两天我们还把从 AMD RX 9070 XT 移植过来的 100% 开源独立 CUDA 引擎（路线 A，`Development/hip-port/`）连肝了 16 个阶段（切换 `.f16.f16.f16.f16` 满速指令、CPU 静态权重安培座位预洗牌、LLVM IR 16B 对齐升级消除 14 万条单字节 `u8` 读写、`2-shfl` 跨阶段寄存器直通、ViT 四核尾部 16B 合并写等），把独立引擎的 1080p 耗时从最初的 `208.7 ms`（`v0.1.0` 时 `57.1 ms`）一路压到了 **`31.83 ms`（720p `14.15 ms`）**，甚至顺手揪出了几个可以反向回哺给 RX 9070 XT 仓库的优化点。

### 1. 常规 DX12 游戏包：`OptiScaler-DLSS5-RTX30-0.2.0.zip`（以《剑星》为例）

1. **找准 `.exe` 目录**：先退出游戏，找到游戏真正的渲染进程 `.exe` 所在目录（注意虚幻 4/5 游戏通常在 `<游戏根目录>\Binaries\Win64\`，例如《剑星》是 `StellarBlade\SB\Binaries\Win64\`，不要解压到外层的启动器目录）。
2. **备份原文件**：如果该目录原本自带 `amd_fidelityfx_dx12.dll`（如《剑星》自带一个 6.6MB 的同名文件），先把它备份到别处。
3. **完整解压覆盖**：把压缩包里的**全部 37 个文件**解压进该目录（**切勿只挑 4 个文件拷**，包内 26KB 的 `amd_fidelityfx_dx12.dll` 加载器必须与 28MB 的 `amd_fidelityfx_upscaler_dx12.dll`、`fakenvapi.dll`、`D3D12_Optiscaler` 等配套文件一起工作）。
4. **进游戏设置**：在游戏画面设置中开启 **DLSS** 或 **FSR** 超分均可（包内已配置自动将 FSR 输入转接到 DLSS + DLSS 5 神经渲染）。
   - **快捷键**：按 **`F6`** 实时开关 DLSS 5 对比效果；按 **`Insert`** 打开 OptiScaler 菜单调节参数。
   - **风格切换**：默认 `OptiScaler.ini` 为 `TransferStrength=1.0 / ColourStrength=1.0`（自然平衡、转视角不闪烁）；若喜欢浓烈重打光效果，可将目录内的 `OptiScaler-增强风格.ini`（`1.5 / 1.1`）复制改名为 `OptiScaler.ini`。

### 3. 万能窗口缩放包：`Magpie-DLSS5-RTX30-0.2.0.zip`（以《光环》等任意窗口化游戏为例）

2. **使用方法**：
   - 把游戏设为 **窗口模式**（推荐 `1280×720` 或 `1600×900` 窗口）；
   - 右键以 **管理员身份** 启动包内的 `Magpie.exe`；
   - 默认缩放配置已选好 **`DLSS5-RTX30-PTX`**（第一级跑原生 `DLSSNR` `Preset 2`，第二级跑 `DLSS_SR` 放大到 4K/2K 全屏）；
   - 点击 **“3 秒后缩放”** 并切回游戏窗口即可全屏生效（或直接按快捷键 **`Alt+Shift+A`** 启停缩放）。
3. **大幅跃升的 60Hz 电视体验**：
