#900p production rounding audit (2026-09-14)

Scope: `Development/900p/game-flags.txt`, current repository runtime selection and the **last writer** of each CSO in `scripts/bench.ps1`. C32 is excluded. This is a source/build-contract audit; this agent did not independently prove every deployed CSO hash matches these sources. Runtime flags cannot recover compile-only switches, and reading an earlier compile command can produce the wrong contract.

## Key findings with source lines

1. **MH fused FFN differs strongly from legacy reference.** Flags FUSED_FFN/FP8_ACTIVATIONS/FP8_STREAM=1 select fused execution (`src/native_c64.h:49`, `:127`, `:145`, `:180`). `shaders/native_wave_ffn_fused.hlsl:64` accumulates all expand K32 tiles in FP32, with no H per group; `:39-43` uses the polynomial without intermediate H, and `:65-76` quantizes once. Contract `:89` similarly carries its FP32 accumulator across all K. **Do not remove its final H:** bench`:320` first writes HW_QUANTIZE=1, but bench`:329` overwrites the same fp8act filename without that define. Default0 makes shader`:91-93` run F(H(acc)). PRECISE_CHAIN=1 is passed at the last write, so polynomial multiply/add must not contract to FMA. Legacy `multihead_reference.hip:54-59` rounds every K32 and several polynomial steps.

2. **Projection has multiple contracts.** `native_wave_project.hlsl:187` fast branch carries accumulator across K32; legacy`:190` uses H(previous+separate-group-sum). Initial residual is H(feature*scale) only in the scalar branch`:158-160`. Stream output with DIRECT_CAST skips final H at`:198-201`; raw/f32 variants retain final H/F(H). Bench`:166`,`:170`,`:187-199` enables matrix residual and direct cast, choosing matrix residual for non-mapfeature variants only. `src/native_c64.h:85-91` decomposes each scale into three E4M3 diagonal matrices; shader`:151` seeds from three WMMA operations **without initial H**. Therefore replacing every residual with H(feature*scale), or deleting only the group H while still resetting each K32 sum, does not reproduce production. Scalar-mapfeature and matrix-residual variants need separate modes.

3. **QKV must stay raw FP32 until fast normalization.** `native_wave_qkv_normalize.hlsl:65` is continuous FP32 MAC, unlike reference QKV's per-group H. With QKV_FAST2 default0,`:86-98` squares raw FP32 values and sums32 channels in FP32, computes unrounded rsqrt×scale, and`:106-110` scales/casts directly to E4M3. Bench`:307` passes QKV_FAST2 from an environment variable but does not assign it to1 itself (inherited build environment remains a qualification). FAST2=1 instead half-casts squares then uses a matrix sum`:74-84`. Neither path uses legacy half-square-pair and half reduction tree. A fast QKV output cannot feed the existing exact normalization without changing the intended contract.

4. **MH attention fast2 also changes normalization math.** Bench`:132` enables ATTN_FAST2,`:308` builds the selected FP8 fast2 CSO. `native_wave_attention_direct.hlsl:132` adds bias and calls fast_exp_raw without the legacy score H;`:42` only converts the affine result to half for the bit transform. Exponent sums use an F16-input/FP32-output MMA`:142`, unrounded reciprocal`:146`, and direct FP8 probability cast`:150-151`. AV MAC spans both K32 segments`:158-161`, then direct FP8 cast`:163` with no final H. Reference retains half denominator trees, half reciprocal/probability and H after each AV group. Ordinary softmax is not equivalent to either path.

5. **C512 FFWD:** current flags WAVE_SPLIT_FFWD=0 alone does not establish scalar execution when SPLIT_STREAM8=1 selects the stream kernel (`src/native_split.h:100-101`,`:124`). `native_wave_split_ffwd_parallel.hlsl:150`,`:168`,`:184` accumulates mix/expand/contract in FP32, with stage-end H at`:153`,`:170`,`:186`. Activate removes polynomial's intermediate H when FAST_EPILOGUE is selected (`:46-49`), but its argument is still H(acc) at`:170`. Legacy deep_reference split_mix/expand/contract (`:44-46`) inserts H every32 products. The currently disabled FP8 FFWD experiment must not be presumed active merely because FP8_OPERANDS=1.

6. **ViT:** bench`:214` explicitly sets FAST_ACCUMULATE/FAST_EPILOGUE=1. BLOCK_M4 packed expand `native_wave_vit_blocked.hlsl:106-111` carries FP32 across1024 K and applies fast activation without intermediate H. Packed reduce split-K `:227` accumulates each K partition in FP32; combine`:248-250` starts H(residual*scale), adds all four FP32 partials without H between them, then F(H(total)). Deep reference`:56-57` has both group H and partition-combine H. QKV fused (`native_wave_vit_qkv.hlsl:60`,`:90`) and its normalization must be matched as the actually selected fused path, not inferred from the older project entry's two512 partitions.

7. **ViT attention FP8:** `native_wave_vit_attention_fp8.hlsl:42` accumulates denominator via MMA,`:53-58` carries AV in FP32,`:65` retains final F(H(acc*inverse)). The new deep_reference `_fast` variants`:63-65` already describe these broad arithmetic changes; scalar summation order remains a separate issue from WMMA exactness.

8. **Decoder projection:** `native_wave_decoder_entry.hlsl:94-110` fast branch removes per-K32 and inter-partition H but retains H on final total; residual merge still H at`:137-139`/`:162-164`. Do not remove that final projection H or merge H when translating deep_reference decoder_project2x. Memory layout/FP16-output flags are separate from these rounding points.

## Priority

First align ISA_HALF across exact benchmarks (already done by parent), keeping exact modules as rollback/oracle. Then implement **independent fast exports** for the clearly specified MH dense family: continuous WMMA acc across K16/K32, final epilogues matching each production variant. Start with fused FFN, whose real production CSO can validate the entire expand→contract pair. Next mapfeature projection versus matrix-residual projection as distinct modes, and QKV together with fast normalization. Next ViT packed dense/partition combine. Change attention reductions only with direct production stage comparisons; they are not an incidental H deletion.

The measured exact900p tiled148ms versus naive344ms is a useful implementation baseline. It still evaluates legacy rounding, so it is not yet an apples-to-apples runtime comparison with900p production D3D fast math. Existing golden exact output should remain; fast parity needs its own production oracle.
