### 2. 相对于 `v0.2.0` 的六刀底层改进详解

#### 第一刀（`PTX V2.2`）：32 位双通道 SWAR 无分支量化 + 原生 `cp.async.mbarrier.arrive` 异步绑定（耗时立降 `~7%`）
- **消除谓词分支与 `bfe` 拆通道**：在 `v0.2.0` 中，全网 8,944 处 `cvt.rn.satfinite.e4m3x2.f16x2`（把两个 FP16 打包成两个 FP8）虽然用了 `+2.0h` 处理次正规数，但仍需把高低 16 位拆成两个标量通道、用 2 个谓词寄存器（`.pred`）分别判断 `lo < 2^-6` 和 `hi < 2^-6` 再用 `selp` 合并（每次打包 29 行 PTX，用掉 8 个 `.b32` + 2 个 `.pred`）。`V2.2` 改用 `set.lt.u32.f16x2` 生成双通道 16-bit 比较掩码 + 单条 `lop3.b32 ..., 0xca` 同时选择高低两个通道，消灭了全部 `.pred` 谓词寄存器与拆通道指令。
- **原生异步拷贝屏障绑定**：在 `v0.2.0` 中，TMA `cp.async.bulk` 被降级为 `cp.async.cg + cp.async.commit_group + cp.async.wait_group 0` 当场同步等待。`V2.2` 将 `FB04 / FB05 / FB06` 共 316 处异步拷贝直接改写为 Ampere 原生支持的 **`cp.async.mbarrier.arrive.shared::cta.b64`**，把异步拷贝完成信号直接挂到原版内核已有的 `mbarrier` 上，删掉了当场阻塞等待，让全局显存预取与计算真正重叠。

#### 第二刀（`PTX V2.3`）：`PRMT` 符号扩展把 FP8 解码从 10 条压至 8 条指令（再快 `~1.5%~2%`）
- 在 `v0.2.0` 中，把 1 个 `.b32`（4 个 E4M3 字节）解包为两个 `f16x2` 需要 10 条指令（奇偶两路各 5 条：掩码取绝对值、掩码取符号位、移位对齐、合并符号、`HMUL2` 乘 $2^8$）。
- `V2.3` 利用 `sm_86` 的字节置换指令 `PRMT` 原生自带的**符号位复制模式（selector `0x8 ~ 0xb`）**：用 `prmt.b32 dst, reg, reg, 0xa280`（或 Low/High 下的 `0x9180 / 0xb3a2`）在抽取字节的同时自动把符号位 `bit 7` 扩展到高字节 `bit 8`，随后只需 `and 0x017f017f` + `shl 7` + `mul.rn.f16x2 0x5c005c00`，将每次解码从 **10 条指令压至 8 条指令（每路仅 4 条 SASS）**。

#### 第三刀（`PTX V2.4`）：按需即时解码（JIT Decode）与死亡临时寄存器池回收（再快 `~0.8%~1.5%`）
- 在 `v0.2.0 ~ V2.3` 中，每遇到一段连续的矩阵乘（`mma_run`，最长 64~96 条 `mma`），生成器都在开头一口气把所有输入操作数全部解码成 FP16 临时寄存器，导致峰值有 `80 ~ 160` 个 `.b32` 临时寄存器同时存活。
- `V2.4` 对每个 `mma_run` 建立精确的 `first_use / last_use` 与写覆盖（clobber）生命周期表：只在操作数第一次被 `mma` 使用（或被前序输出覆盖）前即时解码，一旦过完该操作数的最后一条消费者 `mma`，立即将其占用的两个 `.b32` 临时寄存器归还空闲池 `free` 供后续操作数复用，将各模块解码池峰值从 `64/80/96/160/128/144` 大幅压低至 `40/56/56/56/112/80/20`。

#### 第四刀（`PTX V2.6`）：Low/High K16 布局 + `mapped` 操作数零拷贝直连（消灭 21,712 处 `PRMT`，再快 `~2.0%~2.3%`）
- 这是非常关键的一步结构跳跃：在 `v0.2.0` 的“偶奇 K16（`byte 0, 2` 与 `byte 1, 3`）”布局下，虽然非 `mapped` 操作数解包方便，但对于同一核内刚由两个 `f16x2` 寄存器 `(low, high)` 打包而成、紧接着又喂给下一条 `mma` 的 **`mapped` 操作数**，因为 `low` 装的是 `(elem 0, elem 1)`、`high` 装的是 `(elem 2, elem 3)`，为了凑齐偶奇顺序 `(elem 0, elem 2)` 和 `(elem 1, elem 3)`，每次都不得不额外发射两条 `prmt.b32 ..., 0x5410 / 0x7632` 指令！
- `V2.6` 将线程内 K32 拆解统一切换为 **Low/High K16 布局（第一相直接算 `byte 0, 1` 即 `low`，第二相直接算 `byte 2, 3` 即 `high`）**：
  - 非 `mapped` 操作数用 `prmt 0x9180 / 0xb3a2` 依然保持 8 条指令不变；
  - 而全网所有的 **`mapped` 操作数直接把原始 `(low, high)` 寄存器原封不动填进 `mma` 指令操作数槽位，连一条 `PRMT` 或 `MOV` 都不需要（0 拷贝、0 指令、0 临时寄存器）**！仅这一招就在生成路径上直接抹掉了 **21,712 条 `mapped PRMT` 指令**（在 `FB00` 单帧相当于省掉 6,000 万次动态 PTX 事件）。

#### 第五刀（`PTX V2.7`）：基于 CUDA Occupancy API 的 C32 四核 `168` 寄存器精准驻留（再快 `~0.9%`）
- 在 `V2.6` 消灭大量 `mapped` 临时寄存器后，`FB00 (C32)` 的寄存器压力显著下降。通过直接调用 CUDA Driver API `cuOccupancyMaxActiveBlocksPerMultiprocessor` 对真实 `.cubin` 逐核扫描，我们将 `FB00` 中的 4 个主力核（`pre_block`、`inpview`、`ds_wait`、`outview`）精准卡在 `.maxnreg 168`，使其每 SM 硬件驻留从 `8 Warps/SM (2 CTA)` 跃升至 **`12 Warps/SM (3 CTA)`（并发驻留提升 `+50%`）**，且几乎不增加局部栈开销。

#### 第六刀（`PTX V2.9_fast → V3.1_pack5`）：$2^{-8}$ 统一乘法 + `HMNMX2 |R2|` 折叠 + 单条 `LEA` 舍入，将打包从 13 条腰斩至 5 条 SASS（再快 `~4.3% ~ 5.0%`）
- 在完成前五刀后，我们通过构造 `2×2` 正交消融探针（独立旁路 Pack vs 独立旁路 Decode）发现：尽管 `V2.2` 的 SWAR 打包只需 13 条核心 SASS，但在真实网络中它与解码激烈争抢整数/置换管线，独立旁路 Pack 依然握着 `0.42 ~ 0.57 ms` 的整帧敏感度！
- 为此我们连续推导出两代微架构级打包算法（`V2.9_fast` 9 条 SASS → **`V3.1_pack5` 5 条 SASS**）：
  1. **用单条 `mul.rn.f16x2 ..., 0x1c001c00`（乘以 $2^{-8}$）统一 Normal 与 Subnormal 双分支**：
     因为 FP16 与 E4M3 的指数偏置差 `15 - 7 = 8` 恰好等于次正规数阈值差 `14 - 6 = 8`，乘以 $2^{-8}$ 后，所有 `< 2^-6` 的 E4M3 次正规数会自动落入 FP16 硬件次正规数区完成尾数右移对齐，正规数与次正规数的 7-bit 编码统统对齐在每个 16-bit 半字的 `bits [13:7]` 上——原本需要算两次再 `lop3` 选择的两条路径合二为一！
  2. **利用 `HMNMX2 |R2|` 硬件绝对值修饰符免费消掉去符号指令**：
     将按位清符号 `and.b32 a, src, 0x7fff7fff` 改写为浮点 `abs.f16x2 a, src`，`ptxas -O4` 会将其 100% 折叠进饱和截断指令 `HMNMX2 R0, |R2|, 448, 448, PT` 的源操作数绝对值硬件位 `|R2|` 中，0 条指令完成去符号与 `448.0` 钳位。
  3. **单条 `LEA` 移位加偏置 + `LOP3` 拼符号 + `PRMT` 抽字节**：
     用单条 `LEA R5, R0, 0x7f007f, 0x1`（左移 1 位对齐至高字节同时完成符号对称 Ties-toward-Zero 舍入），接 `LOP3 0xb8` 拼回原符号位、`PRMT 0x4431` 抽出高字节，整个 `f16x2 → e4m3x2` 打包核心在 `sm_86` 上只剩 **5 条 SASS 指令**：
     ```sass
     HMNMX2 R0, |R2|, 448, 448, PT ;             // 1. 硬件取绝对值 + 448.0 饱和截断
     HMUL2  R0, R0, 0.00390625, 0.00390625 ;     // 2. 乘 2^-8 统一对齐 Normal/Subnormal
     LEA    R5, R0, 0x7f007f, 0x1 ;              // 3. 左移 1 位至高字节 + 对称舍入进位
     LOP3.LUT R0, R2, 0x7f007f00, R5, 0xb8, !PT ;// 4. 原位拼回符号位 bit 15 / bit 31
     PRMT   R7, R0, 0x4431, RZ ;                 // 5. 抽取两个高字节合成 e4m3x2 (.b16)
     ```
- 这一刀将 38 个活跃核的非 NOP 静态 SASS 从 `V2.7` 的 `175,685` 条 → `V2.9_fast` 的 `163,944` 条 → **`V3.1_pack5` 的 `152,076` 条（两步累计砍掉 `23,609` 条打包指令，`-13.44%`）**，并在两轮 `V2.9_fast`（快 `~2.5%`）与两轮 `V3.1_pack5`（再快 `~1.8%~2.4%`）共 96 次正式 ABBA 配对中 **24/24 个正反方向 100% 全胜**，彻底填平了 Pack 侧的性能缺口！

### 常用快捷键与注意事项
- **`F6` 键**：在两个 OptiScaler 游戏包中，游戏中按 **`F6`** 可随时开关 DLSS 5 神经渲染，实时对比开启前后的光影与材质效果。
- **`Insert` 键**：呼出 OptiScaler 设置菜单，可在 `DLSS Neural Rendering` 栏微调风格（`Style`）与强度。
- **防闪烁默认强度与增强风格切换**：
  - 常规包默认配置 `TransferStrength=1.0 / ColourStrength=1.0`，避免《剑星》等游戏快速转动视角触发运动遮罩回退时产生明暗闪烁；
  - 若喜欢更浓郁的风格化光影，只需将目录内的 `OptiScaler-增强风格.ini`（`1.5 / 1.1`）复制覆盖为 `OptiScaler.ini` 即可。
- **《鬼武者》曝光源切勿手改**：RE Engine 的线性 HDR 范围在 `0～512`，包内已配好 `WhitePointSource=1`（读取游戏原生曝光），切勿在菜单中改为 `1.0x`，否则高光未归一化会导致画面发绿。
