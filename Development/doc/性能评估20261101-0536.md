## 一、 评估命题定义与 12 轮（`V3.2 ~ V4.3`）完整运行账本

### 1.1 明确收窄的阶段收官命题（严格遵循《0105 审核意见》第 3、5 节规范）
1. **系统约束与晋升门定义**：
   - 沿用已适配 Ampere 的封存 Host 补丁路径（`V3.1_pack5 / V3.8 / V4.0` 屏蔽 15 个 Fatbin 槽位与 PE checksum 后的其余全文件字节 SHA 完全相同），本优化阶段不新增 Host CPU 调度代码、内嵌权重段或函数参数 ABI 改写，保持稳态每帧 82 次 NVAPI Kernel 发射序列与 15 个 PE 原槽位 `ptxas -O4` 编译（总长 `266,414,592 B`）不变；
   - 性能晋升门：在未插桩 `bench_sky.exe`（720p `sky`、900p/1080p `scene`，每进程 50 warmup / 80 iter，串行正反序 ABBA / BAAB）中，候选必须同时通过 **首轮（`timed`）三档六方向全胜 + 复测确认轮（`repeat`）三档六方向全胜**（共 12/12 个正反方向均快于同轮 `1.00×` 基线）；
   - 质量验收门：精确候选要求所测末帧相对当前 `1.00×` 基线严格 `0 bit-diff`（`maxabs = 0, nonfinite = 0`）；实证/近似候选要求相对基线三档 `PSNR >= 50 dB`、`maxabs <= 1/64`、`nonfinite = 0` 且 720p 天空 `变号 = 0`（注：在三档确定性基准帧上实测输出 `0 bit-diff` 的经验 `Pack4` 候选仍保留实证/近似标签，不升格为任意输入激活有界的数学证明）。
2. **本报告的核心命题（区分“预设搜索闭环阶段收官”与“数学/物理绝对下界”）**：
   - 响应 [《0105 审核意见》](性能评估20261101-0105-审核意见.md) 第 4 节指出的三项未排除方向，我们将搜索树从 4 个分支扩展为 **7 个预设分支**，继续执行了 `V3.6 ~ V4.3` 共 8 轮构造性实测，从中成功兑现了 **`PTX V3.8`** 与 **`PTX V4.0`** 连续两代晋升（使 38 个活跃核静态非 NOP SASS 从 `V3.1_pack5` 的 `152,076` 压降至 `145,461`，1080p 两轮四进程 GPU median 配对均值压入 **`10.987 ~ 10.995 ms`**，8 个单进程 median 范围为 `10.920 ~ 11.022 ms`），并最终在 `V4.3` 使全部 7 个预设分支达到 `K = 3` 连续未晋升剪枝条件（`Open = 0`）。
   - **本报告申请的是“固定边界、既定晋升门与 7 个预设分支 `K=3` 搜索规则下的工程阶段收官（锁定 `PTX V4.0` 为本轮搜索最终胜出基线）”**；本报告**不宣称** `K=3` 剪枝构成约束空间内所有 PTX 程序的完备性枚举证书，**不宣称** `5-SASS / 4-SASS / 7-SASS Quad` 构成已证 ISA 下界，亦**不宣称**在理论上已不存在任何更快的未测程序。第 四 节显式列出了当前仍未覆盖的细粒度组合区域与未来重开触发条件。

## 三、 为什么《0105 审核意见》第 4 节指出的三大方向能够催生 `V3.8 / V4.0` 并在 `V4.3` 达到阶段收敛？

1. **分支 5（有界/正零生产者特化与 32 位直解 `UP-Pair`）——兑现两代晋升后进入微幅振荡区**：
   - **第一阶段兑现（`PTX V3.8`）**：通过对全网 8,944 处 `cvt.rn.satfinite.e4m3x2.f16x2` 做独立 `mov/cvt` 定义链证明，定位出 680 处恒为 `+0.0` 的正零转换；剔除引起 `FB00 upsample` 寄存器变化的前端模块后，仅在 `FB04/05/06` 折叠 500 处正零（直接替换为无算术核心的 `mov.b16 dst, 0`），使 38 核非 NOP SASS 从 `152,076 → 150,672`、`FB04 qkv_512` 的 `STL/LDL` 从 `40/29 → 33/22`，两轮 12/12 方向全胜晋升 `V3.8`。
   - **第二阶段兑现（`PTX V4.0`）**：针对全网 4,744 处独立 `cvt.rn.f16x2.e4m3x2`（`UP`）100% 源自 2,372 个 32 位半字拆分 `mov.b32 {%rs_lo, %rs_hi}, %r_src32` 的结构，通过同块检查与跨块 CFG 全路径无覆写证明（`CFGProof`），先按纯 UP 原型资源（`REG/STACK/STL/LDL` 不增且 `CTA/SM` 不降）筛选出 34 个活跃入口（直解 1,288 处 `UP` 并删除 644 个半字拆分），再叠加 `FB02/03/05/06` 的 4-SASS `Pack4` 重新编译并通过联合验收（最终联合版中 `FB02 ds_wait 164→166`、`ViT projection_chained 145→148`、`ViT projection_wait 145→146` 三个入口 REG 微增 1~3 个，但 `STACK/STL/LDL` 仍为 `0/0/0` 且 `CTA/SM` 保持 `3→3` 不变）；使 38 核非 NOP SASS 再降 `5,211` 条至 **`145,461`**（`STL/LDL` 降至 `99/100`），两轮 12/12 方向全胜晋升 `V4.0`（1080p 四进程 GPU median 配对均值：首轮 `11.0625 → 10.9950 ms`，`repeat` `11.0595 → 10.9868 ms`；8 个单进程 median 范围 `10.920 ~ 11.022 ms`）。
   - **第三阶段收敛（`V4.1 ~ V4.3`）**：在 `V4.0` 基线上继续测试补入 `FB04 pool / FB06 UP`（`V4.1`）、`FB00/01 Pack4` 与 7-SASS `Pack4_Quad`（`V4.2`、`V4.3`，将静态非 NOP SASS 进一步压至 `143,963 ~ 143,992`、`STL/LDL` 压至 `94/94`），虽在 720p 与 900p 多组配对中呈正收益（如 `fb123_pack4_quad_clean` 赢下 5/6 个方向），但在 1080p 反向或 900p 反向始终存在 `-0.097% ~ -0.182%`（约 `0.008 ~ 0.020 ms`）的单向回退，未通过预设六向全胜门，按 `K = 3` 规则完成剪枝。
2. **分支 6（`FB02 / FB03` 原位全字节可逆 2× Shared 表示与单入口/单段精选）——满 `K = 3` 剪枝**：
   - `V3.6` 构造了保留 `7f/ff -> ±480` 语义的全 256 字节可逆原位映射，消除了 `V3.5 shadow` 模式的 3× 写冗余，并在 `V3.6 ~ V3.8` 中依次测试了 `fb2_inplace`、`fb3_inplace`、`fb23_inplace`、`fb23_fast_inplace`、`fb3_selective_fast_inplace`、`fb2_epoch_shadow/fast`、`FB03` 四个单入口各自独立剥离、`regdown`、`noinp` 以及正向双入口 `fb3_inp_up_exact / fast`，均未能同时在三档六个方向跑赢基线。
3. **分支 7（`FB04 / FB05` 异步 `cp.async` 发布后协同解包耦合表示）——满 `K = 3` 剪枝**：
   - `V3.6` 的 `fb45-shared-audit.json` 证实 `FB04/05` 不存在脱离 `cp.async` 的纯寄存器 `st.shared` 生产周期；在 `V3.6 ~ V3.8` 中测试的 `async_fb4`、`async_fb5`、`async_fb45`、清零单核 `88 B STACK` 的 `async_qkv_only`（900p `+0.125%/+0.172%`，但 720p/1080p 为负）、16 字无分支展开 `async_qkv_unrolled` 以及 `async_pool_only` 均未取得全档双向净胜（协同刷新引入 `LDS/算术/STS/BAR` 并同时改变 Shared 容量、寄存器、Spill 与排程，新增成本与读端节省尚未单独分解）。

## 四、 未测区域边界声明、未来重开触发条件与阶段收官裁决请求

遵循《0105 审核意见》第 4、5 节与《0536 审核意见》第 3、4 节的要求，我们将当前未覆盖的探索空间与工程收官边界明确如下：
1. **未测区域边界声明（不宣称已在数学上穷尽）**：
   - **细粒度子集组合空间**：在 `V4.1 ~ V4.3` 中，我们按模块/入口规则测试了 `Pack4`、`7-SASS Pack4_Quad` 与 `UP-Pair` 的代表性子集（如 `fb123_pack4_quad_clean` 涵盖 556 组 Quad），但并未穷举 $2^{38}$ 种逐入口/逐转换位点的指数级组合子集；
   - **实证 `Pack4` 与静态等价参照范围**：`PTX V4.0` 在 `FB02, FB03, FB05, FB06` 上启用了省去前端 `min.f16x2 448` 的经验 `Pack4`（在全部 27 次三档测试帧检查中相对 `V3.8` 为严格 `0 bit-diff`，并可传递确认在此测试集上与 `V3.1_pack5` 输出哈希一致），但该属性属于在测试基准输入上的实证表现，不等同于对任意未见极端 HDR 输入的静态范围证明；`PTX V3.8` 新增的 500 处正零折叠则是**相对 `V3.1_pack5` 静态可证明等价**并通过所测整网逐位检查的基线（注：非整条移植路径对原厂原生 FP8、RN-even 或 FP32 真值的全域位等价证书；生产版本 `v0.3.0` 仍保持 `V3.1_pack5`）；
   - **动态硬件计数器盲区**：受当前 WSL/Windows 环境无 Nsight Compute (`ncu`) 硬件性能计数器权限限制，本项目的微架构分析基于静态 SASS、官方 Occupancy API、NVAPI 逐核硬件时间戳与破坏性探针，未直接采集动态 `issued` 指令数、Shared 银行冲突（bank conflicts）或管线停顿原因（stall reasons）。
