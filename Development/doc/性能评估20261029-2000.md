## 一、 核心结论：`PTX V3.1_pack5` 已兑现的收益与最新正交缺口定性

### 1.1 `PTX V3.1_pack5`（5-SASS Pack）的算法、指令削减与多轮实测提速
1. **从 13 条 → 9 条 → 5 条核心 SASS 的三代打包演进**：
   - `PTX V3.1_pack5` 在 `V2.9_fast`（9 条核心 SASS）基础上做了两步微架构级精简：① 将整数按位清符号 `and.b32 a, src, 0x7fff7fff` 改为浮点 `abs.f16x2 a, src`，使 `ptxas -O4` 将取绝对值 100% 免费折叠进 `HMNMX2 R0, |R2|, 448, 448, PT` 的源操作数硬件绝对值修饰符 `|R2|` 中；② 用单条 `LEA R5, R0, 0x7f007f, 0x1`（`shl 1 + add 0x007f007f`，符号对称 Ties-toward-Zero 舍入）替代 `SHF.R + LOP3 + LEA + IADD3` 四条偶奇位提取指令。
   - 独立 `O4` 小核实测证实，单对 `f16x2 → e4m3x2` 打包的核心 SASS 从 `V2.7` 的 **13 条**、`V2.9_fast` 的 **9 条** 直接压缩至 **`V3.1_pack5` 的 5 条**：
     `HMNMX2 |R2|` → `HMUL2 2^-8` → `LEA 0x7f007f, 0x1` → `LOP3 0xb8` → `PRMT 0x4431`。
   - 在 `FB00..FB06` 全部 **38 个实际发射活跃核** 中，非 NOP 静态 SASS 指令数从 `V2.7` 的 `175,685` 条 → `V2.9_fast` 的 `163,944` 条 → **`V3.1_pack5` 的 `152,076` 条**（相比 `V2.9_fast` 再净减 **`11,868` 条 / `-7.24%`**；相比 `V2.7` 累计净减 **`23,609` 条 / `-13.44%`**）。按含固定尾部 NOP 口径则从 `176,431` → `164,659` → **`152,807` 条**（相比 `V2.9_fast` 净减 `11,852` 条）。
2. **此前两轮 12 个方向汇总 + 本轮 12 个逐 pass 比较全部快于 `V2.9_fast`**：
   - 在 [v31/README.md](../ptx-patcher/v31/README.md) 的两轮（`first` + `repeat`，共 48 次正式 50/80 正反 ABBA/BAAB 配对）中，`V3.1_pack5` 在全部 12 个方向汇总上一致快于 `V2.9_fast`：
     - **第 1 轮（`first`）**：720p `5.82800 → 5.71275 ms (-1.978%)`、900p `8.52750 → 8.38475 ms (-1.674%)`、1080p `11.98600 → 11.57100 ms (-3.462%)`；
     - **第 2 轮（`repeat`）**：720p `5.87675 → 5.77950 ms (-1.655%)`、900p `8.64600 → 8.46125 ms (-2.137%)`、1080p `11.27500 → 11.12300 ms (-1.348%)`；
   - 在本报告第 2.3 节新增的五版本四轮正反序扫描（三档×4 pass = 12 个逐 pass 比较）中，`V3.1_pack5` 在 **全部 12 个逐 pass 比较中再次 100% 快于同轮 `V2.9_fast`**：
     - **本轮四轮均值**：720p **`5.731000 → 5.618250 ms (-1.967%)`**、900p **`8.516750 → 8.376750 ms (-1.644%)`**、1080p **`11.558000 → 11.070750 ms (-4.216%)`**。
3. **数值与画质边界**：
   - 单通道 65,536 个 `uint16` 位型中，`V3.1_pack5` 与近似基线 `V2.9_fast` 有 `65,378` 个（`99.759%`）逐位一致（相差 158 个位型，均仅差 1 ULP）；与精确 E4M3（`V2.7` / `V2.9_exact`）相比则有 `65,370` 个（`99.747%`）逐位一致（相差 166 个位型，均仅差 1 ULP）。整网相对 `V2.9_fast` 的 PSNR 为 **`61.738 / 60.821 / 59.645 dB`**（`maxabs` `0.004395 / 0.007813 / 0.008301`），全部运行 `nonfinite = 0`，720p 天空测试 `变号 = 0`。

### 1.2 站在 `PTX V3.1_pack5` 新基线上的 `2×2` 正交消融结论与优先级裁决

本轮我们以 **`V3.1_pack5`** 为新原点，构建破坏性探针 `P0_ZeroPack`（将 pack 替换为单条 `cvt.u16.u32`）、`P1_V31_NoDec`（保持 `V3.1_pack5` 的 5-SASS pack，仅旁路 non-mapped 8 指令解码与 `vlh_t` 临时池）及 `P2_Both`（同时应用 `P0` 与 `P1`），连同前代基线 `V2.9_fast` 进行了同轮五版本正反序实测（60 次未插桩 + 30 次 NVAPI 捕获），得出以下两项结论：

1. **结论一：升级到 `V3.1_pack5` 后，进一步用破坏性 `P0_ZeroPack` 替换 Pack 在未插桩 900p/1080p 测试中已不再呈现全 pass 同向正收益（差值均值变号），工程上决定暂为 Pack 收官，不再优先投入已测试的 Pack 路线**。
   - 对比三轮评估中各自基线相对 `P0_ZeroPack` 的未插桩四轮均值表现（不同轮次独立测量，非跨轮守恒相减）：
     - **`1100` 轮 `V2.7`（13-SASS Pack）`− P0`**：720p `+0.414500 ms` / 900p `+0.570250 ms` / 1080p `+0.573250 ms`（三档 12/12 pass 全为正）；
     - **`1506` 轮 `V2.9_fast`（9-SASS Pack）`− P0`**：720p `+0.344250 ms` / 900p `+0.297500 ms` / 1080p `+0.387000 ms`（三档 12/12 pass 全为正）；
     - **本轮 `V3.1_pack5`（5-SASS Pack）`− P0`**：
       - **720p**：未插桩 4 个 pass 为 `+0.103, +0.186, +0.119, +0.207 ms`（4/4 为正，均值 **`+0.153750 ms`**，中位数 `+0.152500 ms`），而 NVAPI 82 核合计为 **`-0.057421 ms`**；
       - **900p**：未插桩 4 个 pass 为 `+0.180, -0.719, +0.282, -0.197 ms`（2 正 2 负方向变号，均值 **`-0.113500 ms`**，中位数 `-0.008500 ms`），而 NVAPI 82 核合计为 **`+0.205414 ms`**；
       - **1080p**：未插桩 4 个 pass 为 `-0.695, +0.234, +0.239, +0.090 ms`（3 正 1 负方向变号，因 pass 0 出现一次较大负差使四次均值拉低为 **`-0.033000 ms`**，中位数为 `+0.162000 ms`），而 NVAPI 82 核合计为 **`+0.334003 ms`**。
   - 同时，在已移除解码的 `P1_V31_NoDec` 上继续移除 5-SASS Pack（`P1_V31 → P2_Both`），未插桩三档均值为 **`-0.198250 / -0.295500 / -0.659000 ms`**（12 个 pass 中 11 个为负），NVAPI 82 核合计为 **`-0.508492 / -0.222950 / -0.587239 ms`**（6/6 pass 全为负）。
   - **工程裁决**：本轮未插桩 900p/1080p 去 Pack 未检出稳定同向的正收益（虽 720p 未插桩与 900p/1080p NVAPI 仍存在一定正敏感度，且不能将一次负样本拉低的均值当作数学上“可能性 100% 耗尽”的等效证明），结合研发阶段继续叠加 `quad+up`（`v31_pack5_quad`）在 1080p 回退的实验事实，当前将 **`V3.1_pack5`** 定为 Pack 侧胜出方案，不再优先在 Pack 上消耗迭代资源。

2. **结论二：在 `V3.1_pack5` 基线上，移除 `Non-mapped Decode` 与解码临时池（`V3.1_pack5 − P1_V31_NoDec`）在未插桩与 NVAPI 两个计时域的全部 18 个 pass 中 100% 保持同向正敏感度（未插桩 `0.574 / 0.925 / 1.363 ms`），是后续唯一明确的高优先级方向**。
   - 在 `V3.1_pack5` 基线上单变量移除 non-mapped 解码与 `vlh_t` 临时池（`V3.1_pack5 → P1_V31_NoDec`），在**全部 12 个未插桩 pass 与全部 6 个 NVAPI pass（18/18）上方向一致为正**：
     - **未插桩四轮均值**：720p 下降 **`0.573750 ms (-10.21%)`**（`5.618250 → 5.044500 ms`）、900p 下降 **`0.925250 ms (-11.05%)`**（`8.376750 → 7.451500 ms`）、1080p 下降 **`1.362500 ms (-12.31%)`**（`11.070750 → 9.708250 ms`）；
     - **NVAPI 82 核合计**：720p 下降 **`0.578252 ms (-10.23%)`**、900p 下降 **`0.886809 ms (-10.46%)`**、1080p 下降 **`1.983821 ms (-17.37%)`**。

## 三、 `V3.1_pack5 → P1_V31_NoDec` 的 38 活跃核 G1 / G2 / G3 互斥三分法账本（经官方 CUDA Occupancy API 验证）

为严格排除手算寄存器除法的偏差，我们对 `V3.1_pack5` 与 `P1_V31_NoDec` 编译出的真实 cubin 逐核调用了 CUDA Driver API `cuOccupancyMaxActiveBlocksPerMultiprocessor`（传入 `v23/profile.json` 实测 `block` 线程数与 `dynamic_shared` 字节数，逐核 API 返回值已保存在 [性能评估20261029-2000-实验数据.json](性能评估20261029-2000-实验数据.json) 的 `cuda_occupancy_api_audit` 字段中），将 38 个活跃 FP8 核划分为三个**完全互斥**的分组：

1. **G1 组（23 个核：静态 `STL/LDL/STACK` 恒为 `0/0/0B`，且 `cuOccupancyMaxActiveBlocksPerMultiprocessor` 返回的 `Active CTA/SM` 完全不变）**：
   - 包含 `FB00` 的 `upsample`（32 线程单 warp 核，`REG 205 → 202`，CUDA Occupancy API 实测返回值均为 **`8 CTA/SM (8 Warps/SM)`** 不变）与 `FB05` 的 `projection_chained / wait`（128 线程核，`REG 145 → 138`，API 实测返回值均为 **`3 CTA/SM (12 Warps/SM)`** 不变），以及其余 20 个零 Spill 且 API 驻留不变的活跃核。
   - 注：G1 组排除了静态 Spill 变化与理论驻留台阶跃升，但其净敏感度仍包含移除解码指令、缩短依赖链及改变指令排程/预取距离的综合效应，不等同于孤立的纯 ALU 周期计时器。
2. **G2 组（7 个核：静态 `STL/LDL/STACK` 恒为 `0/0/0B`，但 `cuOccupancyMaxActiveBlocksPerMultiprocessor` 实测返回值发生跨阶跃升）**：
   - 包含 `FB05 (ViT)` 的 **4 个零 Spill 主力核**（`ffn_contract_chained 179→155`、`ffn_expand_chained 180→152`、`ffn_expand_publish 172→144`、`qkv_chained 197→164`，API 驻留均从 **`2 → 3 CTA/SM (8 → 12 Warps/SM)`** 跃升）与 `FB04 (C512)` 的 **3 个零 Spill 核**（`proj_pool_512 180→162` API 驻留从 **`2 → 3 CTA/SM (8 → 12 Warps/SM)`** 跃升；`proj_512 141→112` 与 `final_head_512 136→106` API 驻留从 **`1 → 2 CTA/SM (8 → 16 Warps/SM)`** 跃升）。

## 四、 最终结论与后续优化优先级

`PTX V3.1_pack5` 在研发两轮 12 个方向汇总与本轮 12 个逐 pass 比较中再次稳定快于 `V2.9_fast`。进一步用破坏性 `P0_ZeroPack` 替代 Pack，在本轮未插桩 900p/1080p 测试中差值均值变号，未得到稳定同向的正收益（720p 未插桩与 900p/1080p NVAPI 仍存在一定正敏感度，反映出不同计时域与采样的差异）。

因此，当前没有证据支持继续采用已测试的额外 Pack 候选（如 1080p 回退的 `v31_pack5_quad`），工程上将 **`PTX V3.1_pack5`** 定为当前生产推荐版本，并将后续优化重点转向在未插桩与 NVAPI 全部 18 个 pass 中一致为正的 **Decode（解码）敏感度**（其中 `72% ~ 80%` 的核内净敏感度集中在 30 个零静态 Spill 核 `G1 + G2` 中）。这一优先级决策不宣称 Pack 理论空间已被证明为零，也不将破坏性探针差值直接视作可全额回收的性能预算。
