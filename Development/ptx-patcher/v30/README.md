# PTX V3.0：K-Step 解交错 + B/A-Stationary 保序拓扑重排实验

**结论：保持 `PTX V2.9_fast`（SHA256 `55b518762bbe4d43fbe71f838352e23584d719736d86dd45437f4f50fc135f5c`）为当前生产推荐版，不晋升 `V3.0` DLL。**

本实验将解码临时寄存器池峰值从 `56 / 56 / 56 / 112 / 80 / 20` 压降至 `36 / 36 / 36 / 36 / 36 / 12`（38 个活跃核静态 `STL/LDL` 从 `109/104` 降至 `85/84`，`FB01` 最大 `STACK` 从 `104 B` 降至 `88 B`），并在全部 51 次运行（3 次 1/1 快验 + 48 次 50/80 正式运行）中相对 `V2.9_fast` 实现 **严格 `0 bit-diff`（`maxabs = 0.0, nonfinite = 0`）**；但在三档分辨率未插桩正反 ABBA/BAAB 配对计时中未取得全档双向净提速，从而在实证上分离出了“解码临时寄存器池 spill 效应”与“解码 ALU/PRMT 指令流本身效应”。

## 1. 候选定义与静态资源变化（相对 `V2.9_fast`）

复现脚本：[run_v30.py](run_v30.py)、[eval_20261028_reorder_audit.py](../../doc/eval_20261028_reorder_audit.py)。
- **`v30_all`**（SHA256 `e7d764f4a97d2505f456b1d938d227a2d97d65f375392a34e0c677b29989fe4e`）：对 `FB00..FB06` 全部启用保序拓扑重排（固定原 run 入口 `orig_start`，在 `expanded_rw` 依赖图中纳入 `mapped` 的 `(low, high)` 隐式源，严格要求 `has_hazard == False` 与 `backup_moves == 0`）。38 个活跃核 `STL/LDL` 减少 `24/20` 条，非 NOP SASS 减少 `195` 条（`163,944 → 163,749`），解码指令数（`encoded_operands`）不变。
- **`v30_fb14`**（SHA256 `61a62fa82350a2b8165f24d05866f0e73fd090dd512ac8db1f0c9c01407962d8`）：仅对 `STACK / STL / LDL / REG` 发生显著下降的 `FB01` 与 `FB04` 启用重排，其余模块保持 `V2.9_fast` 原二进制不变。

## 3. 物理意义：分离“解码临时池寄存器压力”与“解码指令流本身成本”

在不减少非 `mapped` 解码指令条数（每对仍为 8 条指令）的前提下，将各模块解码临时池峰值从 `56~112` 压至 `<= 36` 并削减 `FB01` 22% 的静态 `STL/LDL` 与 `FB04 qkv_512` 20% 的静态 `STL/LDL`，整帧耗时基本持平（`< 0.2%` 且 900p/1080p 正反变号）。这直接证实：**`P1_V29_NoDec` 探针测出的 `0.648 ~ 1.732 ms` 敏感度主要源于 `45,976` 条非 `mapped` 解码指令本身的执行与依赖链成本，而非解码临时池在当前 `V2.9_fast` 下引起的少量剩余 `STL/LDL` 溢出**。
